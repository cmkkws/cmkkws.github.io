Yun 등 (2024) — RCT 수치 추출

  • 논문: Automatically Extracting Numerical Results from Randomized Controlled Trials with Large Language Models (Yun 등, 2024 · MLCB / PMLR 252)
  • 요약: 메타분석용 임상 수치 추출 성능을 검증하기 위해 무작위 임상시험(RCT) 120편·699문항의 정답 자료를 구축하고 8개 LLM의 추출 정확도와 통계적 영향을 비교했다.
  • 결과: 문항 내 요구 수치를 모두 맞힌 전체 일치율은 GPT-4가 이분형 65.5%·연속형 48.7%로 가장 높았고, 타 치료군·시점 수치 오선택과 추출 가능 값에 대한 x(unknown) 출력이 주요 오류로 나타났다.
  • 한계: 소규모·제로샷 평가이며, 모델별 문맥 한도·입력 분할·생성 설정이 달라 모델 자체의 효과와 전처리·프롬프트 효과를 분리하기 어렵다.

2. 평가 과제·사례·프롬프트·지표

  • 오류 사례 1 — 결과 유형 분류 (부록 Table 6): 입력 survival에 대해 정답은 continuous(생존 기간)이나 GPT-4는 binary(생존 여부)로 분류했다. 지표명만으로 이분형·연속형 구분이 모호할 때 오분류가 발생한다.
  • 오류 사례 2 — 이분형 수치 추출 (부록 Figure 6): 아미포스틴 사용 여부에 따른 중증 구내염 문항(총 환자 40명, 치료군 발생률 0%, 대조군 25%). 대조군 비율 25%를 사건 수 25명으로 추출하고 군별 표본 수에는 x를 출력했다(4개 중 1개 일치).
  • 오류 사례 3 — 연속형 수치 추출 (부록 Figure 7): 일상생활 수행능력 치료 결과 추출 문항. 입력 발췌 표에 치료 전 기초값만 제시되었으나, GPT-4가 기초값을 치료 후 결과로 출력한 시점 귀속 오류다(6개 중 표본 수 2개만 일치).

  • 프롬프트 규칙 (커밋 1bc768d4 GPT 템플릿 기준)

    • 설명 없이 YAML만 출력하고, 확인·계산 불가 값은 "x", 치료 전·후 값 중 치료 후(post-intervention), 복수 시점 중 관심 시점 근접값 또는 마지막 시점을 선택하도록 지시한다.
    • 결과 유형 분류 코드에는 본문을 함께 넣는 with-abstract-results 템플릿도 포함되어 있다.

Pronesti 등 (2025) — URCA 근거 검색·결론 분류

  • 논문: Query-driven Document-level Scientific Evidence Extraction from Biomedical Studies (Pronesti·Bettencourt-Silva 등, 2025 · ACL, 28034–28051쪽)
  • 요약: 상반된 임상 근거가 섞인 문헌에서 연구별 결론을 판정하기 위해 CochraneForest(923문항)를 구축하고, 논문별 균등 검색과 질의 중심 군집화를 결합한 URCA 파이프라인을 제안했다.
  • 결과: Mistral-Large 기반 URCA의 결론 분류 F1은 67.3%였으며, GPT-3.5에서는 GraphRAG(56.6%) 대비 5.8%p 높은 62.4%(상대 개선 10.3%)를 기록했다.
  • 한계: 공개 전문이 확보된 연구와 상반된 결론이 포함된 forest plot으로 대상이 제한되며, 정답 근거 구간(span) 주석이 없어 검색 실패와 추론 실패를 정량 분리하기 어렵다.

1. 데이터 구축·분할

2. 평가 과제·사례·프롬프트·지표

  • 오류 사례 1 — 목표 결과 지표(누공 폐쇄)와 타 결과 지표 혼동 (Figure 6, Appendix C.2): 줄기세포 치료와 위약의 누공 폐쇄 효과를 비교하는 질문에서, 군집화를 제외한 방식은 동일 논문 내 다른 지표(CDAI·PDAI)의 비유의성 문구를 근거로 선택해 차이가 없다고 오판했다.

  • 오류 사례 2 — 질의 중심 군집화를 통한 결과 지표 분리: 누공 폐쇄율, 폐쇄 시간, 기타 임상 지표를 다루는 검색 청크들을 의미 군집별로 묶은 뒤 질문 관련 근거만 추출해 지표 간 혼동을 줄였다.

  • 프롬프트 구조 (Appendix D, Figure 7a~c)

    • 질문 생성: 리뷰 제목·초록·plot 설명·결론 후보를 입력받아 임상 질문 생성.
    • 근거 추출: 검색 청크에서 수치·통계적 유의성·결론을 추출하되, 상반된 근거가 있으면 양쪽 모두 보존.
    • 결론 판정: 목표 결과(outcome_measured), 근거(rationale), 결론(conclusion), 결론 ID(conclusion_id)를 JSON으로 출력.

3. 연구 설계·도구

4. 평가 결과

한계·후속 과제: 문항별 정답 근거 구간(span)을 추가 주석하여 검색 단계의 누락과 추론 단계의 실패를 분리 평가할 필요가 있다. 자료·코드: 논문·부록

Wang 등 (2025) — TrialMind 단계별 근거 합성

  • 논문: Accelerating clinical evidence synthesis with large language models (Wang·Cao 등, 2025 · npj Digital Medicine 8:509)
  • 요약: 문헌 검색·선별부터 연구 특성·결과 수치 추출 및 메타분석 표준화까지 단계별 LLM 파이프라인(TrialMind)을 검증하기 위해 암 치료 리뷰 100개·포함 연구 2,220개로 TrialReviewBench를 구축·평가했다.
  • 결과: 4대 암 치료 주제의 결과 수치 추출 정확도는 6584%로 GPT-4 추출 후 수동 표준화 기준선(5054%)보다 높았으나, 하위집단·결과 지표 혼동과 추출 실패가 남았다.
  • 한계: 암 치료 문헌에 평가가 집중되어 있고 문헌 선별 후보군에 정답 연구를 사전 포함했으며, 전문가 협업 평가 표본이 작다.

1. 데이터 구축·분할

2. 평가 과제·사례·프롬프트·지표

  • 오류 사례 1 — 전체 치료 환자군과 NSCLC 하위집단 혼동 (본문 6쪽): 비소세포폐암(NSCLC) 하위집단의 치료 결과를 추출해야 하나, 논문 초반부에 제시된 전체 CAR-T 치료 환자군 수치를 잘못 선택했다.

  • 오류 사례 2 — 간암 국소 종양 진행 메타분석 비교 (보충자료 Figure 3): 간암 microwave ablation 대 radiofrequency ablation 비교에서 생성된 TrialMind forest plot은 전문가 선호도가 높았으나, 기준 리뷰와 포함 연구 수 및 일부 효과 추정치에서 차이가 있었다.

  • 프롬프트 구조 (보충자료 Figure 10~13 및 공개 코드 235426b0)

    • 특성 추출: 필드별 값과 정수형 문단 출처 ID(source_id, 최대 3개)를 JSON으로 반환하며, 미기재 시 NP 출력.
    • 결과 추출: 목표 환자군(cohort)과 결과 지표(target_outcome)에 맞춰 군별 환자 수와 정량 결과 추출.
    • 코드 표준화: 원시 추출 결과를 PICO에 따라 치료군 분류(classify_arms) → 데이터 통합(consolidate_data) → 통계량 계산(calculate_statistics) 순으로 처리하는 Python 코드 생성.

한계·후속 과제: 암 이외의 질환과 더 큰 전문가 협업 환경에서도 단계별 추출·표준화 파이프라인의 정확도와 시간 절감 효과가 유지되는지 검증이 필요하다. 자료·코드: 논문·보충자료 · TrialReviewBench · 코드

Wang 등 (2025) — LEADS 문헌 분석 미세조정

  • 논문: A foundation model for human-AI collaboration in medical literature mining (Wang·Cao 등, 2025 · Nature Communications 16:8361)
  • 요약: 문헌 검색·선별·구조화 추출을 수행하는 소형 특화 모델을 구축하기 위해, 리뷰·논문·임상시험 등록자료(ClinicalTrials.gov)를 연결한 LEADSInstruct(633,759건)로 Mistral-7B를 미세조정했다.
  • 결과: 수동 검수 기준 시험 결과 수치 추출 정확도는 LEADS 56.7%·GPT-4o 55.7%였으나, 전체 테스트셋 자동 채점에서는 LEADS 16%·GPT-4o 21%로 정답 원천과 채점 방식에 따른 격차가 컸다.
  • 한계: 등록자료와 출판 논문 간 수치·단위·시점 표현 불일치로 인해 자동 채점의 한계가 있으며, 30K 장문 학습·추론에 대용량 GPU 자원이 필요하다.

1. 데이터 구축·분할

2. 평가 과제·사례·프롬프트·지표

  • 사례 1 — 수치와 단위·시점·분모의 구조화 출력 (Figure 4d): 시험 결과 추출 시 결과 수치(0.58)뿐 아니라 통계량 유형(MEAN), 측정 단위(Scores on a scale), 시점(1 week), 분모 단위 및 군 표본 수(31)를 함께 반환한다.

  • 사례 2 — 등록자료 자동 채점과 원문 수동 검수의 격차: 등록자료 정답과 출판 논문의 단위·수치 표기 차이로 인해 시험 결과 수치의 자동 Exact Match는 LEADS 16%(GPT-4o 21%)였으나, 원문 대조 수동 검수(75건)에서는 LEADS 56.7%(GPT-4o 55.7%)로 나타났다.

  • 프롬프트 구조 (보충자료 Extended Figure 14~17 및 공개 코드 263a9e57)

    • 논문 전문(paper_content)과 목표 필드·군·결과 정의를 결합해 과제별 고정 JSON 스키마로 출력한다.
    • 연구 특성은 요청 필드 수(num_field)와 출력 배열 길이를 맞추도록 지시하며, 시험 결과는 파라미터 유형·단위·시점·분모 단위·분모 값과 군별 수치를 반환한다.

3. 연구 설계·도구

4. 평가 결과

한계·후속 과제: 임상시험 등록자료와 논문 본문 간 정답 불일치·합성 주석 오류를 줄이고, 실제 문헌고찰 환경에서 전문가 보조 효과를 추가 검증할 필요가 있다. 자료·코드: 논문·보충자료 · LEADSInstruct · 모델 가중치 · 코드

Pronesti 등 (2025) — 강화학습 기반 수치 추론

  • 논문: Enhancing Study-Level Inference from Clinical Trial Papers via Reinforcement Learning-Based Numeric Reasoning (Pronesti·Lorandi 등, 2025 · EMNLP, 30357–30373쪽)
  • 요약: 문장 근거에서 곧바로 결론을 생성하는 대신 군별 임상 수치를 추출해 효과량을 계산하도록 Qwen2.5-7B를 SFT·GRPO 강화학습으로 학습시키고, 수치 추출과 연구별 결론 정확도를 평가했다.
  • 결과: RL 모델의 전체 수치 일치율(EM)은 CochraneForest 42.2%·RCT 자료 41.2%로 기반 모델(14.9%·20.3%)보다 높았으나, 수치 정답과 추론 설명의 논리적 일관성이 항상 함께 달성되지는 않았다.
  • 한계: 기본 이분형·연속형 수치와 공개 전문 보유 연구로 대상이 제한되며, 결과표 간 Accuracy/F1 열 표기 불일치가 존재한다.

1. 데이터 구축·분할

2. 평가 과제·사례·프롬프트·지표

검토한 연구의 공통 흐름은 자료 확보 → 입력 정리 → 추출 문항·정답 구축 → 평가셋 구성 → 모델·처리 조건 비교 → 구조화·계산 → 채점·오류 분석으로 정리된다. 문헌 검색, 미세조정, 음성 전사는 각 과제에 필요한 단계에 추가된다.

1. 자료 수집 — 평가할 원천 자료 확보

  • 임상시험 문헌·등록자료: PMC의 공개 전문을 확보하고, 기존 리뷰에 포함된 연구·forest plot·ClinicalTrials.gov 등록자료를 연결한다. 리뷰의 포함 문헌 목록은 검색 정답으로, 특성 표·forest plot·등록 레코드는 추출 정답의 출처로 활용한다. 예: TrialMind의 리뷰–포함 논문 연결, LEADS의 PMID–NCT ID 연결.
  • 기관 진료기록·검사 보고서: 특정 진료 기간·수술·검사 종류를 기준으로 기록을 선정하고, 환자별 문서 또는 보고서별 파일로 묶는다. 예: OphthoACR의 수술 환자별 종단 기록, 안과 검사 PDF의 장비·보고서 유형별 표본.
  • 설계한 실험 자료: 확인할 오류가 드러나도록 시나리오를 만들고 여러 사람이 수행·발화한 자료를 수집한다. 예: 치주기록 연구의 결손치·정정 명령·두 자리 숫자를 포함한 5개 시나리오와 3명 발화자 녹음.

2. 입력 정리 — 문서 구조와 수치 문맥 보존

  • 형식 변환: XML·텍스트 PDF는 본문·표를 추출해 Markdown 또는 텍스트로 변환한다. 스캔 기록은 OCR, 음성은 ASR을 거쳐 모델이 처리할 텍스트를 만든다.
  • 정보 연결: 치료군·결과 지표·시점·표 헤더, 눈의 좌우·치아 위치처럼 숫자의 의미를 결정하는 정보를 함께 유지한다. 임상 기록에서는 약어·단위·시력 표기를 정규화하기도 한다.
  • 길이 대응: 긴 입력은 청크로 나누어 출처·날짜 메타데이터를 붙이거나, 긴 문맥 모델에 전문을 제공한다. 예: URCA는 검색 청크를 군집화하고, LEADS의 공개 추론 코드는 앞 29,000토큰을 사용한다. 길이 제한을 위한 분할과 관련 근거를 고르는 검색은 별도 처리다.

3. 문항·정답 구축 — 무엇을 어떤 단위로 맞힐지 정의

  • 문항 단위: 문헌은 ‘연구 × 치료 비교 × 결과 지표’, 진료기록은 ‘환자 × 변수 × 시점’, 검사·음성은 ‘보고서 또는 치아·부위 × 필드’로 평가 항목을 구성한다.
  • 출력 스키마: 목표 필드와 자료형을 미리 정한다. 예: 이분형 결과는 두 군의 사건 수·표본 수 4개, 연속형 결과는 평균·SD·표본 수 6개이며, 다른 과제는 단위·시점·분모·군 ID를 추가한다.
  • 정답 확보: 원문을 독립 주석한 뒤 합의하거나, 리뷰 표·forest plot·등록자료의 구조화 값을 정답으로 전환한다. 자동 구성 자료에는 수동 검수 표본을 더한다. 예: Yun의 독립 주석·합의, LEADS의 등록자료 정답과 원문 대조 검수.
  • 예외 규칙: 미기재 값, 여러 시점, 치료 전후 값, 표준편차 역산, 좌우·군이 불분명한 경우의 처리 기준을 둔다. x·NP·null 같은 유보 표시는 각 스키마에 맞춰 사용한다.

4. 벤치마크 구성 — 고정된 입력·정답으로 조건 비교

  • 평가 과제 분리: 결과 유형 분류·수치 추출·최종 결론 판정처럼 출력이 다른 과제를 구분하고, 같은 평가 자료에 여러 모델·처리 방식을 적용한다. 검색은 정답 문헌 회수율, 추출은 필드 또는 문항 일치율로 채점한다.
  • 자료 수와 문항 수 구분: 논문 한 편·환자 한 명에서 여러 평가 항목을 만들 수 있다. 예: RCT 120편에서 699문항을 구성하거나, 보고서 20건에서 값 684개를 채점한다. 같은 보고서의 반복 실행은 안정성 평가이며 고유 자료 수를 늘린 것은 아니다.
  • 학습 여부에 따른 분할: 미세조정 연구는 학습·검증·시험 자료를 나누고, 제로샷·프롬프트 비교 연구는 고정 평가 표본을 사용한다. 예: 수치 추론 연구는 확장 자료 1,864/208문항과 별도 CF 725·RCT 413문항을 구분한다.
  • 평가 범위 명시: 전체 과정의 성능과 일부 단계의 성능을 구분한다. 예: TrialMind의 선별 후보에는 정답 논문이 포함되도록 구성하므로, 선별 점수만으로 실제 검색 누락까지 평가한 것은 아니다.

5. 비교 실험 — 모델과 처리 방식의 효과 확인

  • 기본 비교: 같은 입력·과제에서 범용 LLM과 의료 특화 모델, 기반 모델과 미세조정 모델, 단순 프롬프트와 단계별 처리를 비교한다.
  • 과제별 구성: 여러 논문의 근거를 찾아야 하면 RAG·군집화를, 정형 수치를 반복 추출해야 하면 지시학습·수치 보상을, 고정 필드 보고서는 상세 지시·스키마 제약을 적용한다. 이들은 검토 자료에서 사용한 접근의 유형이다.
  • 요소 제거 실험: 제안 기법의 일부를 제거해 성능 변화를 확인한다. 예: URCA의 균등 검색·군집화 제거, 수치 추론의 본문·표 분리 및 설명·보상 방식 비교. 여러 기능을 한 번에 바꾼 비교는 결합 방식 전체의 효과로 해석한다.

6. 구조화·계산 — 추출값을 분석 가능한 결과로 변환

  • 형식 검증: JSON·YAML을 파싱하고 필수 키·자료형·결측·수치 범위·필드 간 일관성을 확인한다. 출력 형식을 맞추는 검사와 값·군·시점이 맞는지 확인하는 검사는 구분한다.
  • 계산 단계 분리: 원문 수치를 추출한 뒤 표준화·통계 계산을 수행한다. 예: TrialMind는 생성한 Python 코드로 군을 통합·표준화하고, 수치 추론 연구는 추출값으로 효과량·신뢰구간·결론을 계산한다.
  • 근거·시간 연결: 결과에 출처 ID·원문 문구·날짜를 연결하거나, 여러 시점 값을 누적한 뒤 목표 시점 값을 선택한다. 예: TrialMind의 출처 ID, OphthoACR의 근거 문구와 3개월 검사값 정리.

7. 채점·오류 분석 — 정확도와 실제 사용 효과 구분

  • 정확도 층위: 개별 필드 일치율, 문항 전체 일치율, 출력 형식 정확도, 최종 결론 정확도를 나눠 본다. 일부 숫자가 맞거나 결론이 같더라도 필요한 모든 필드가 정확한 것은 아니다.
  • 오류 분류: 수치 누락·환각, 다른 군·시점·좌우·치아로의 오귀속, 단위·통계량 혼동, 형식 오류로 묶어 원문과 대조한다. 자동 채점과 전문가 판정이 다르면 정답 원천·표현·단위를 추가 확인한다.
  • 실무 평가: 일부 연구는 사람 단독·AI 단독·AI 보조를 비교해 정확도와 시간을 함께 측정한다. 검토자 개입과 전후처리 시간의 포함 범위를 함께 기록한다.

성능 비교 종합

아래의 우세 조건은 각 논문 안에서 같은 평가 자료·지표로 비교한 결과다. 논문 간 데이터 난도·분모·채점 방식이 달라 수치 크기만으로 전체 1위를 정하지 않는다. EM은 한 문항의 요구 수치 전체가 일치한 비율이다.

1. 임상시험 문헌의 수치 추출

2. 근거 검색·연구별 결론 판정

3. 진료기록·검사 보고서·음성 처리

4. 비교에서 드러난 공통 경향

  • 문헌 수치 추출: 단계별 추출·코드 표준화와 과제 특화 학습이 해당 연구의 기준선보다 높은 결과를 보였다. 다만 LEADS의 자동 채점과 RL 모델의 CF 대형 모델 비교처럼 과제·채점 조건에 따른 예외가 있다.
  • 근거 검색: URCA에서는 출처 균형과 의미 군집화를 유지한 조건이 높았다. 복잡한 검색 기법의 명칭보다 목표 결과와 관련된 근거를 확보·정리했는지가 비교의 핵심이다.
  • 보고서 구조화: 값 정확도와 형식 정확도의 우세 방식이 달랐다. 상세 지시와 스키마 제약을 모두 결합한 방식이 최상이라고 확정하는 실험은 이 비교에 포함되지 않았다.
  • 실무 검토: OphthoACR에서는 AI 보조가 정확도, AI 단독이 보고된 처리 시간에서 우세했다. 로컬 시력 추출과 치주 음성 연구는 항목별 편차를 보여 주지만, 대안 방식과의 직접 비교 결과는 제시하지 않는다.
