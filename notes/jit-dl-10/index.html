Attention Mechanism

Transformer의 핵심 연산은 Attention이다.

Attention은 현재 Token의 Representation이 Sequence 내 다른 Token들의 Representation으로부터 필요한 정보를 선택적으로 수집하도록 만든다.

핵심 구조는

\[\boxed{ \text{Query} \rightarrow \text{Key와 비교} \rightarrow \text{Attention Weight} \rightarrow \text{Value의 Weighted Sum} }\]

Input Sequence

Sequence Length를

\[\boxed{ S }\]

라고 하고 Model Hidden Dimension을

\[\boxed{ d_{\mathrm{model}} }\]

이라고 하자.

입력 Hidden-State Matrix는

\[\boxed{ X \in \mathbb R^{ S\times d_{\mathrm{model}} } }\]

각 Row가 하나의 Token Representation에 해당한다.

Query Projection

DL-01의 Linear Layer를 사용하여 Query를 생성한다.

\[\boxed{ Q = XW_Q }\]

Weight Shape을

\[\boxed{ W_Q \in \mathbb R^{ d_{\mathrm{model}}\times d_k } }\]

라고 하면

\[\boxed{ Q \in \mathbb R^{S\times d_k} }\]

Key Projection

동일하게

\[\boxed{ K = XW_K }\]
\[\boxed{ W_K \in \mathbb R^{ d_{\mathrm{model}}\times d_k } }\]

이면

\[\boxed{ K \in \mathbb R^{S\times d_k} }\]

Value Projection

Value는

\[\boxed{ V = XW_V }\]
\[\boxed{ W_V \in \mathbb R^{ d_{\mathrm{model}}\times d_v } }\]

이면

\[\boxed{ V \in \mathbb R^{S\times d_v} }\]

Q/K/V 전체 구조

따라서

\[\boxed{ X \rightarrow Q=XW_Q }\]
\[\boxed{ X \rightarrow K=XW_K }\]
\[\boxed{ X \rightarrow V=XW_V }\]

라는 세 개의 Linear Projection Branch가 만들어진다.

Query의 직관

원자료는 Query를

현재 Token이 찾고자 하는 정보의 탐색 Vector

로 설명한다.

수학적으로는 Token Representation을

\[W_Q\]

를 이용해 Query Space로 Mapping한 Vector다.

Key의 직관

Key는 각 Token이 Query와 비교되기 위해 사용하는 Representation이다.

즉

\[\boxed{ q_i^Tk_j }\]

를 통해 Query \(i\)와 Token \(j\) 사이의 Compatibility Score를 계산한다.

Value의 직관

Value는 최종 Attention Weight가 곱해지는 실제 Content Representation이다.

즉 Key는 얼마나 선택할 것인가를 결정하는 데 참여하고,

Value는 선택된 뒤 무엇을 전달할 것인가를 담당한다.

Attention Score

Query와 Key 사이의 Score Matrix는

\[\boxed{ QK^T }\]

Shape은

\[(S\times d_k) (d_k\times S)\]

이므로

\[\boxed{ QK^T \in \mathbb R^{S\times S} }\]

Score Matrix Element

\((i,j)\)번째 Element는

\[\boxed{ (QK^T)_{ij} = q_i^Tk_j }\]

즉 Token \(i\)의 Query와 Token \(j\)의 Key 사이의 Dot Product다.

Dot Product의 정확한 기하학적 의미

두 Vector \(q,k\)에 대해

\[\boxed{ q^Tk = \|q\|_2 \|k\|_2 \cos\theta }\]

따라서 Dot Product는

  1. 두 Vector의 방향 관계
  2. 두 Vector의 Norm

모두의 영향을 받는다.

Dot Product와 Cosine Similarity 구분

Cosine Similarity는

\[\boxed{ \cos\theta = \frac{ q^Tk }{ \|q\|_2\|k\|_2 } }\]

따라서 원자료의 Dot Product 설명을 엄밀히 하면

\[\boxed{ \text{Dot Product} = \text{Cosine factor} \times \text{vector magnitudes} }\]

Dot Product 자체가 Cosine Similarity와 동일한 것은 아니다.

Scaled Dot-Product

Raw Score를

\[\sqrt{d_k}\]

로 나눈다.

\[\boxed{ Z = \frac{ QK^T }{ \sqrt{d_k} } }\]

Causal Mask

Autoregressive Decoder에서는 미래 Token을 볼 수 없도록 Mask를 추가한다.

\[\boxed{ Z = \frac{ QK^T }{ \sqrt{d_k} } + M }\]

여기서

\[\boxed{ M\in\mathbb R^{S\times S} }\]

Causal Mask의 대표적 형태

Token \(i\)가 Token \(j\)를 볼 수 있는 조건을

\[j\le i\]

라고 하자.

이상화된 Mask는

\[\boxed{ M_{ij} = \begin{cases} 0,&j\le i\\ -\infty,&j>i \end{cases} }\]

로 표현할 수 있다.

Mask와 Softmax

Mask된 위치에서는

\[e^{-\infty}=0\]

이므로 Softmax 이후 Probability가 0이 된다.

즉

\[\boxed{ j>i \Rightarrow A_{ij}=0 }\]

Attention Weights

Score Matrix의 각 Row에 Softmax를 적용한다.

\[\boxed{ A = \operatorname{Softmax} \left( \frac{ QK^T }{ \sqrt{d_k} } + M \right) }\]

Row-wise Softmax

각 Query Token \(i\)에 대해

\[\boxed{ \sum_{j=1}^{S} A_{ij} = 1 }\]

따라서 각 Row는 Key Position들에 대한 Probability-like Weight Vector가 된다.

Weighted Value Sum

최종 Attention Output은

\[\boxed{ O = AV }\]

Shape은

\[(S\times S) (S\times d_v)\]

이므로

\[\boxed{ O \in \mathbb R^{S\times d_v} }\]

Single Query Output

Token \(i\)의 Output은

\[\boxed{ o_i = \sum_{j=1}^{S} A_{ij}v_j }\]

즉 Value Vector들의 Weighted Sum이다.

Scaled Dot-Product Attention

전체 식은

\[\boxed{ \operatorname{Attention}(Q,K,V) = \operatorname{Softmax} \left( \frac{ QK^T }{ \sqrt{d_k} } + M \right)V }\]

이것이 원자료의 핵심 Attention 식이다.

왜 Scaling이 필요한가

Attention Score를 그냥

\[q^Tk\]

로 계산하면 \(d_k\)가 커질수록 Score Magnitude가 증가할 수 있다.

원자료는 이를 Probability Theory의 Variance 계산으로 설명한다.

Scaling Derivation Setup

다음 가정을 둔다.

\[\boxed{ q_i,k_i \text{ are independent} }\]

그리고 각 Component가

\[\boxed{ \mathbb E[q_i] = \mathbb E[k_i] = 0 }\]
\[\boxed{ \operatorname{Var}(q_i) = \operatorname{Var}(k_i) = 1 }\]

이라고 하자.

Dot Product

\[\boxed{ S = q^Tk = \sum_{i=1}^{d_k} q_ik_i }\]

라고 하자.

각 Product를

\[\boxed{ z_i=q_ik_i }\]

라고 정의한다.

Product Mean

독립성에 의해

\[\begin{aligned} \mathbb E[z_i] &= \mathbb E[q_ik_i]\\ &= \mathbb E[q_i] \mathbb E[k_i]\\ &= 0 \end{aligned}\]

따라서

\[\boxed{ \mathbb E[z_i]=0 }\]

Product Variance

\[\operatorname{Var}(z_i) = \mathbb E[z_i^2] - \mathbb E[z_i]^2\]

평균이 0이므로

\[\boxed{ \operatorname{Var}(z_i) = \mathbb E[q_i^2k_i^2] }\]

Independence 적용

\(q_i\)와 \(k_i\)가 독립이므로

\[\mathbb E[q_i^2k_i^2] = \mathbb E[q_i^2] \mathbb E[k_i^2]\]

평균이 0이고 분산이 1이므로

\[\mathbb E[q_i^2]=1, \qquad \mathbb E[k_i^2]=1\]

따라서

\[\boxed{ \operatorname{Var}(z_i)=1 }\]

Dot-Product Mean

Expectation의 선형성에 의해

\[\begin{aligned} \mathbb E[S] &= \mathbb E \left[ \sum_i z_i \right]\\ &= \sum_i \mathbb E[z_i]\\ &= \boxed{0} \end{aligned}\]

Dot-Product Variance

추가로 \(z_i\)들이 서로 독립이라는 가정 아래에서

\[\begin{aligned} \operatorname{Var}(S) &= \operatorname{Var} \left( \sum_i z_i \right)\\ &= \sum_i \operatorname{Var}(z_i)\\ &= \sum_{i=1}^{d_k}1\\ &= \boxed{ d_k } \end{aligned}\]

Standard Deviation

따라서

\[\boxed{ \operatorname{Std}(S) = \sqrt{d_k} }\]

즉 Dimension이 커지면 Typical Score Scale도 증가한다.

Scaling

이제

\[\boxed{ \tilde S = \frac{S}{\sqrt{d_k}} }\]

라고 정의한다.

Scaled Variance

상수배의 Variance 성질에 의해

\[\begin{aligned} \operatorname{Var}(\tilde S) &= \frac1{d_k} \operatorname{Var}(S)\\ &= \frac1{d_k} d_k\\ &= \boxed{1} \end{aligned}\]

Scaling 결과의 조건

여기서

\[\boxed{ \operatorname{Var} \left( \frac{q^Tk}{\sqrt{d_k}} \right)=1 }\]

이라는 결과는 앞의

  • zero mean
  • unit variance
  • independence

가정 아래에서 얻은 것이다.

실제 Transformer의 Q/K가 항상 정확히 이러한 Distribution을 가진다는 뜻은 아니다.

Scaling의 핵심 목적

핵심 직관은

\[\boxed{ d_k\uparrow \Rightarrow \text{raw dot-product scale}\uparrow }\]

를 보정하여 Softmax Input Scale을 안정적인 범위에 유지하는 것이다.

Large Logits와 Softmax

Softmax는 Logit Difference가 매우 커지면 Distribution이 Concentrated될 수 있다.

예를 들어

\[[z_1,z_2] = [20,0]\]

이면 첫 번째 Probability가 거의 1에 가까워진다.

Softmax Jacobian

DL-03에서

\[\boxed{ \frac{ \partial S_i }{ \partial z_j } = S_i( \delta_{ij}-S_j ) }\]

였다.

Distribution이 거의 One-Hot이면 많은 Jacobian Component가 매우 작아질 수 있다.

Gradient 설명의 범위

원자료는 Scaling을 Gradient Vanishing 방지와 직접 연결한다.

정확하게는 Scaling이 지나치게 큰 Attention Logit 때문에 Softmax가 매우 Saturated되는 것을 완화하는 역할을 한다.

하지만

\[\boxed{ 1/\sqrt{d_k} \Rightarrow \text{deep network 전체에서 gradient vanishing이 없음} }\]

을 보장하는 것은 아니다.

Multi-Head Attention

하나의 Attention만 사용하는 대신 여러 Attention Head를 병렬로 사용한다.

Head 수를

\[\boxed{ h }\]

라고 하자.

Head-Specific Projection

Head \(i\)는 자신의 Projection Matrix를 가진다.

\[\boxed{ Q^{(i)} = XW_Q^{(i)} }\]
\[\boxed{ K^{(i)} = XW_K^{(i)} }\]
\[\boxed{ V^{(i)} = XW_V^{(i)} }\]

Head Output

각 Head는

\[\boxed{ \operatorname{head}_i = \operatorname{Attention} ( Q^{(i)},K^{(i)},V^{(i)} ) }\]

를 계산한다.

Head Shape

일반적으로

\[\boxed{ \operatorname{head}_i \in \mathbb R^{S\times d_v} }\]

Concatenation

모든 Head Output을 Feature Dimension 방향으로 연결한다.

\[\boxed{ H = \operatorname{Concat} ( \operatorname{head}_1, \dots, \operatorname{head}_h ) }\]

Shape은

\[\boxed{ H \in \mathbb R^{ S\times hd_v } }\]

Output Projection

Concat 결과를 Output Projection에 통과시킨다.

\[\boxed{ \operatorname{MHA}(X) = H W_O }\]

Output Weight

\[\boxed{ W_O \in \mathbb R^{ hd_v\times d_{\mathrm{model}} } }\]

따라서 최종 Output은

\[\boxed{ \operatorname{MHA}(X) \in \mathbb R^{ S\times d_{\mathrm{model}} } }\]

Head Dimension

많은 Transformer에서는

\[\boxed{ hd_v = d_{\mathrm{model}} }\]

로 구성한다.

Query/Key에서도 흔히

\[d_k = \frac{ d_{\mathrm{model}} }{h}\]

형태를 사용한다.

하지만 이는 Architecture Design이며 필수적인 수학적 조건은 아니다.

MHA의 목적

여러 Head가 서로 다른 Learnable Projection을 사용하므로 서로 다른 Representation Subspace와 Token Interaction Pattern을 학습할 수 있다.

다만

\[\boxed{ \text{head}_1=\text{syntax}, \quad \text{head}_2=\text{semantics} }\]

처럼 Head의 역할이 사전에 고정되어 있는 것은 아니다.

MHA Head Count

MHA에서는

\[\boxed{ h_Q=h_K=h_V=h }\]

즉 Query Head마다 대응하는 독립 Key/Value Head가 존재한다.

Autoregressive Inference

Autoregressive Generation에서는 이전 Token들의 Key와 Value를 매 Step 다시 계산할 필요가 없다.

이미 계산한 Key/Value를 저장해 재사용할 수 있다.

이를

\[\boxed{ \text{KV Cache} }\]

라고 한다.

KV Cache

각 Layer에서 이전 Token들의

\[K, \qquad V\]

를 저장한다.

새 Token이 생성되면 새로운 \(K_t,V_t\)만 추가한다.

왜 Q는 Cache하지 않는가

현재 Step의 Query는 현재 Token이 과거 Key들과 비교하기 위한 것이다.

과거 Query는 다음 Step에서 다시 필요하지 않는 것이 일반적이다.

반면 과거 Key/Value는 모든 미래 Query에서 참조될 수 있다.

MHA KV Cache Scaling

Batch를 \(B\), Sequence Length를 \(S\), Layer 수를 \(L\), KV Head 수를 \(h_{KV}\)라고 하면 KV Cache Element 수는 대략

\[\boxed{ 2BSLh_{KV}d_h }\]

2는 Key와 Value 두 Tensor를 의미한다.

MHA의 KV Head 수

MHA에서는

\[\boxed{ h_{KV}=h_Q }\]

따라서

\[\boxed{ N_{\mathrm{KV,MHA}} \propto h_Q }\]

Multi-Query Attention

MQA에서는 Query Head는 여러 개 유지하지만 Key와 Value Head는 하나만 사용한다.

\[\boxed{ h_Q=h, \qquad h_{KV}=1 }\]

MQA의 Head Sharing

모든 Query Head가 동일한 Key/Value Head를 공유한다.

따라서 KV Cache Head Dimension 측면에서는 MHA에 비해

\[\boxed{ \frac1{h_Q} }\]

수준이 된다.

MQA의 Trade-off

원자료는 MQA에서 KV Cache가 크게 줄어드는 대신 표현력 손실이 존재한다고 설명한다.

이 부분은 일반적인 설계 Trade-off에 대한 설명으로 이해한다.

\[\boxed{ \text{less KV diversity} \leftrightarrow \text{smaller KV cache} }\]

Grouped-Query Attention

GQA는 MHA와 MQA의 중간 구조다.

Query Head 수를

\[\boxed{ h_Q }\]

KV Head 수를

\[\boxed{ h_{KV} }\]

라고 한다.

GQA 조건

일반적인 Grouping에서는

\[\boxed{ h_Q \text{ is divisible by } h_{KV} }\]

로 설정한다.

Group Size를

\[\boxed{ g = \frac{ h_Q }{ h_{KV} } }\]

라고 한다.

Group Meaning

각 KV Head 하나를

\[\boxed{ g }\]

개의 Query Head가 공유한다.

즉

\[\boxed{ \text{Query heads per KV head} = g }\]

MHA와 MQA는 GQA의 극단

MHA:

\[\boxed{ h_{KV}=h_Q \Rightarrow g=1 }\]

MQA:

\[\boxed{ h_{KV}=1 \Rightarrow g=h_Q }\]

GQA는 그 사이의 구조다.

GQA Tensor Shape

Batch까지 포함하면 Query Tensor는 개략적으로

\[\boxed{ Q \in \mathbb R^{ B\times h_Q\times S\times d_k } }\]

Key/Value는

\[\boxed{ K,V \in \mathbb R^{ B\times h_{KV}\times S\times d_k } }\]

로 둘 수 있다.

Logical Expansion

Attention 계산 관점에서 각 Query Head가 대응 KV Head를 사용하도록 Key/Value를 논리적으로 Repeat할 수 있다.

\[\boxed{ K_{\mathrm{expanded}} = \operatorname{Repeat}(K,g) }\]

그러면 Head Axis가

\[h_{KV} \rightarrow h_Q\]

로 맞춰진다.

실제 Repeat에 대한 주의

수학적으로 Repeat로 표현할 수 있지만 실제 구현이 KV Tensor를 메모리에서 물리적으로 \(g\)배 복사해야 한다는 뜻은 아니다.

Broadcast/View 또는 Kernel 내부 Mapping으로 처리할 수 있다.

Head Mapping

0-based Query Head Index

\[i=0,\dots,h_Q-1\]

를 사용한다면 대응 KV Head는

\[\boxed{ r(i) = \left\lfloor \frac{i}{g} \right\rfloor }\]

1-based Index에서는

만약 Query Head를

\[i=1,\dots,h_Q\]

로 표기한다면 대응 KV Head는

\[\boxed{ r(i) = \left\lfloor \frac{i-1}{g} \right\rfloor+1 }\]

원자료 Index 보완

원자료에는 \(i=1,\dots,h_Q\)를 사용하면서

\[\left\lfloor \frac{i}{g} \right\rfloor\]

를 사용했다.

이는 0-based와 1-based Index Convention이 섞일 수 있으므로 여기서는

\[\boxed{ \left\lfloor \frac{i-1}{g} \right\rfloor+1 }\]

로 명확히 한다.

GQA Head Equation

1-based Index를 사용하면

\[\boxed{ O^{(i)} = \operatorname{Softmax} \left[ \frac{ Q^{(i)} ( K^{(r(i))} )^T }{ \sqrt{d_k} } + M \right] V^{(r(i))} }\]

Query Pattern은 독립

GQA에서 여러 Query Head가 같은 K/V를 공유해도 Query Projection은 서로 다르다.

따라서 각 Head는

\[Q^{(i)}\]

가 다르므로 Attention Weight Pattern도 서로 달라질 수 있다.

GQA KV Cache Ratio

MHA 대비 GQA의 KV Cache Head 비율은

\[\boxed{ \frac{ h_{KV} }{ h_Q } }\]

Group Size

\[g=\frac{h_Q}{h_{KV}}\]

를 이용하면

\[\boxed{ \frac1g }\]

KV Cache Memory Formula

Element Size를

\[p = \text{bytes per element}\]

라고 하자.

그러면

\[\boxed{ M_{\mathrm{KV}} = 2BSLh_{KV}d_h\,p }\]

로 근사할 수 있다.

MHA Cache

MHA에서는

\[h_{KV}=h_Q\]

이므로

\[\boxed{ M_{\mathrm{MHA}} = 2BSLh_Qd_h\,p }\]

GQA Cache

GQA에서는

\[\boxed{ M_{\mathrm{GQA}} = 2BSLh_{KV}d_h\,p }\]

따라서

\[\boxed{ M_{\mathrm{GQA}} = \frac{ h_{KV} }{ h_Q } M_{\mathrm{MHA}} }\]

\(h_Q=64,\;h_{KV}=8\)

원자료의 Example에서는

\[\boxed{ h_Q=64 }\]
\[\boxed{ h_{KV}=8 }\]

따라서

\[\boxed{ g=8 }\]

Remaining Cache Fraction

\[\frac{ M_{\mathrm{GQA}} }{ M_{\mathrm{MHA}} } = \frac8{64} = \boxed{ \frac18 = 12.5\% }\]

즉 KV Cache 부분만 보면 MHA의 12.5%가 남는다.

Reduction Percentage

절감률은

\[1-\frac18 = \frac78\]

이므로

\[\boxed{ 87.5\% }\]

따라서

  • 남은 Cache: 12.5%
  • 절감된 Cache: 87.5%

를 구분해야 한다.

“Batch Size 8배” 주의

KV Cache만이 유일한 Memory Bottleneck이고 다른 조건이 동일하다면 이론적으로 더 큰 Batch를 수용할 여지가 생긴다.

하지만 실제 Serving Memory에는

  • Model Weights
  • Runtime Buffers
  • Activations
  • Fragmentation
  • Kernel Workspace

등도 존재한다.

따라서

\[\boxed{ \text{KV cache }1/8 \not\Rightarrow \text{actual maximum batch exactly }8\times }\]

\[A = \begin{bmatrix} 0.804&0.196\\ 0.5&0.5 \end{bmatrix}\]

및

\[\operatorname{head}_1 = \begin{bmatrix} 0.196&0.804\\ 0.5&0.5 \end{bmatrix}\]

를 얻었다.

하지만 이 결과는 제시된 \(X,W_K\)의 직접 Matrix Multiplication과 일치하지 않는다.

따라서 본 재구성에서는 원자료 값을 기록하되, 실제 주어진 Matrix에 맞춰 계산을 수정​하였다.

100. FlashAttention

Naive Attention에서는

\[\boxed{ A \in \mathbb R^{S\times S} }\]

규모의 Intermediate가 발생한다.

Sequence Length가 길어지면 이 Matrix의 저장 및 HBM Read/Write가 큰 비용이 될 수 있다.

101. Quadratic Score Structure

Dense Attention의 Pairwise Score 수는

\[\boxed{ S^2 }\]

따라서 기본적인 Dense Attention Arithmetic Structure 자체는 Sequence Length에 대해 Quadratic하다.

102. FlashAttention의 핵심

원자료는 FlashAttention을

  • Tiling
  • On-chip SRAM
  • Online Softmax

를 이용해 HBM 접근을 줄이는 방법으로 설명한다.

핵심은 전체 Attention Matrix를 HBM에 반복 Materialize하지 않는 것이다.

103. Online Softmax

Tile별로

  • Running Maximum
  • Running Normalization Sum

을 유지하면 전체 Score Row를 한꺼번에 저장하지 않고도 Stable Softmax를 계산할 수 있다.

104. FlashAttention 복잡도 주의

원자료의

\[\boxed{ O(S)\text{ memory} }\]

표현은 Attention Matrix Materialization을 피하는 Memory 관점의 설명으로 이해하는 것이 적절하다.

이것이

\[\boxed{ O(S^2) \text{ dense attention arithmetic} \rightarrow O(S) \text{ arithmetic} }\]

을 의미하는 것은 아니다.

105. GQA와 Inference

Autoregressive Inference에서 매 Token마다 과거 Key/Value를 읽는다.

따라서 KV Cache가 작아지면 단순 VRAM Capacity뿐 아니라 Memory-Bandwidth 측면에서도 이점이 생길 수 있다.

106. MHA vs GQA

MHA:

\[\boxed{ h_Q=h_{KV} }\]

GQA:

\[\boxed{ h_{KV}<h_Q }\]

따라서 GQA는 Query Head 수를 유지하면서 저장해야 하는 K/V Head 수를 줄인다.

107. MQA vs GQA

MQA:

\[\boxed{ h_{KV}=1 }\]

GQA:

\[\boxed{ 1<h_{KV}<h_Q }\]

인 대표적 설정을 생각할 수 있다.

즉 GQA는 KV Sharing 정도를 조절한다.

108. “완벽한 절충” 표현의 주의

원자료는 GQA를 MHA 표현력과 MQA 메모리 효율의 “완벽한 절충”이라고 표현한다.

그러나

\[\boxed{ \text{GQA} = \text{universally optimal trade-off} }\]

라는 수학적 정리가 존재하는 것은 아니다.

이는 현대 LLM에서 자주 선택되는 실용적인 Architecture Trade-off로 이해한다.

109. Architecture Dependency

실제 Model이

  • MHA
  • MQA
  • GQA

중 무엇을 사용하는지는 Model Architecture에 따라 다르다.

GQA가 현대 LLM에서 널리 사용되지만 모든 LLM의 필수 표준 구조는 아니다.

110. MLA 연결

원자료는 GQA 이후의 KV Cache 최적화 사례로 DeepSeek의 MLA를 연결한다.

핵심 아이디어는 KV Representation을 더 작은 Latent Representation을 통해 압축해 Cache 비용을 줄이는 것이다.

111. Latent KV Representation

원자료의 Symbol을 따르면

\[\boxed{ c_t^{KV} \in \mathbb R^{d_c} }\]

이고

\[\boxed{ d_c \ll h\,d_k }\]

인 저차원 Latent Representation을 생각한다.

112. MLA의 Low-Rank 관점

개념적으로

\[\boxed{ \text{high-dimensional KV representation} \rightarrow \text{low-dimensional latent} \rightarrow \text{required K/V representation} }\]

이라는 Learned Low-Rank Projection 구조로 이해할 수 있다.

113. “Eigenvalue Decomposition” 표현 주의

원자료는 MLA를 Key/Value의 “고유값 분해 및 저랭크 압축”이라고 표현한다.

하지만 이 학습자료에 제시된 식만으로 실제 Eigenvalue Decomposition

\[A=Q\Lambda Q^{-1}\]

을 수행한다고 볼 근거는 없다.

따라서 여기서는

\[\boxed{ \text{learned low-rank compression} }\]

으로 표현하는 것이 안전하다.

114. “98% 이상” 표현 주의

원자료는 KV Cache를 98% 이상 압축한다고 서술하지만 해당 수치의 계산 근거는 이 자료 안에 제시되어 있지 않다.

따라서

\[\boxed{ 98\%\text{ reduction} }\]

을 본 자료의 수식으로 증명된 결과로 사용하지 않는다.

정확한 수치는 실제 Architecture Dimension을 기준으로 별도 계산해야 한다.

115. DL-01과 연결

DL-01에서 Linear Projection을

\[\boxed{ Y=XW }\]

로 배웠다.

Attention에서는 바로 이 연산을 세 번 사용한다.

\[\boxed{ Q=XW_Q, \quad K=XW_K, \quad V=XW_V }\]

116. DL-03과 연결

DL-03의 Softmax는 Attention Weight를 만드는 데 사용된다.

\[\boxed{ \operatorname{Softmax} \left( \frac{ QK^T }{ \sqrt{d_k} } + M \right) }\]

Output Vocabulary Softmax와 동일한 함수지만 의미와 적용 Axis가 다르다.

117. LA-03과 연결

Attention은 대부분 Matrix Multiplication으로 구성된다.

\[\boxed{ XW_Q, \quad XW_K, \quad XW_V, \quad QK^T, \quad AV }\]

따라서 Matrix Shape 추적이 핵심이다.

118. LA-12와 연결

Dot Product는

\[\boxed{ q^Tk = \|q\| \|k\| \cos\theta }\]

따라서 Attention Score의 기하학적 해석에는 Inner Product와 Norm 개념이 직접 사용된다.

119. PS-07과 연결

Scaling Factor 유도는 Variance를 사용한다.

\[\boxed{ \operatorname{Var} ( q^Tk ) = d_k }\]

under stated assumptions이고,

\[\boxed{ \operatorname{Var} \left( \frac{ q^Tk }{ \sqrt{d_k} } \right) = 1 }\]

120. DL-05와 연결

Attention도 Differentiable Operation의 조합이다.

따라서 Loss에서

\[\boxed{ A \rightarrow Q,K,V \rightarrow W_Q,W_K,W_V }\]

방향으로 Reverse-mode Autodiff가 적용된다.

121. 핵심 식 — Q/K/V

\[\boxed{ Q=XW_Q }\]
\[\boxed{ K=XW_K }\]
\[\boxed{ V=XW_V }\]

122. 핵심 식 — Scaled Dot-Product Attention

\[\boxed{ \operatorname{Attention}(Q,K,V) = \operatorname{Softmax} \left( \frac{ QK^T }{ \sqrt{d_k} } + M \right)V }\]

123. 핵심 식 — Scaling Variance

가정 아래에서

\[\boxed{ \operatorname{Var}(q^Tk) = d_k }\]

이고

\[\boxed{ \operatorname{Var} \left( \frac{ q^Tk }{ \sqrt{d_k} } \right) = 1 }\]

124. 핵심 식 — MHA

\[\boxed{ \operatorname{head}_i = \operatorname{Attention} ( XW_Q^{(i)}, XW_K^{(i)}, XW_V^{(i)} ) }\]

그리고

\[\boxed{ \operatorname{MHA}(X) = \operatorname{Concat} ( \operatorname{head}_1, \dots, \operatorname{head}_h ) W_O }\]

125. 핵심 식 — GQA Group Size

\[\boxed{ g = \frac{ h_Q }{ h_{KV} } }\]

각 KV Head를 \(g\)개의 Query Head가 공유한다.

126. 핵심 식 — GQA Head Mapping

1-based Index에서는

\[\boxed{ r(i) = \left\lfloor \frac{ i-1 }{ g } \right\rfloor+1 }\]

127. 핵심 식 — GQA Cache Ratio

\[\boxed{ \frac{ M_{\mathrm{GQA}} }{ M_{\mathrm{MHA}} } = \frac{ h_{KV} }{ h_Q } = \frac1g }\]

128. 혼동하기 쉬운 부분 — Dot Product

Dot Product는 Cosine Similarity 그 자체가 아니다.

\[\boxed{ q^Tk = \|q\|\|k\|\cos\theta }\]

이므로 Magnitude와 Angle 모두 영향을 준다.

129. 혼동하기 쉬운 부분 — Attention Probability

Attention Weight가 합 1이라는 이유만으로 이를 Token Generation Probability와 동일하게 해석하면 안 된다.

Attention Softmax는 Key Position 선택 Weight다.

Vocabulary Softmax는 다음 Token Distribution이다.

130. 혼동하기 쉬운 부분 — Scaling

\[1/\sqrt{d_k}\]

는 실제 Attention Logit의 분산을 무조건 정확히 1로 만드는 Magic Constant가 아니다.

원자료의 i.i.d., zero-mean, unit-variance 가정 아래에서 그렇게 유도된다.

131. 혼동하기 쉬운 부분 — Mask

Decoder-only Autoregressive Attention에서는 Causal Mask가 중요하다.

Mask 없이 계산한 Self-Attention Example은 Bidirectional Attention과 같은 형태가 될 수 있다.

132. 혼동하기 쉬운 부분 — MHA

여러 Head가 있다고 해서 각 Head가 반드시 사람이 해석 가능한 서로 다른 Linguistic Role을 담당한다고 보장되지는 않는다.

Learned Representation이다.

133. 혼동하기 쉬운 부분 — MQA

MQA의 KV Cache 절감은 정확한 구조적 결과지만 “표현력이 반드시 특정 비율로 감소한다”는 공식은 없다.

품질 Trade-off는 실제 Model과 Training에 의존한다.

134. 혼동하기 쉬운 부분 — GQA

GQA의 핵심은 Query Head 수를 줄이는 것이 아니다.

\[\boxed{ h_Q }\]

는 유지하면서

\[\boxed{ h_{KV} }\]

를 줄이는 것이다.

135. 혼동하기 쉬운 부분 — GQA Repeat

수식에서 Key/Value를 Repeat한다고 써도 실제 KV Cache를 Query Head 수만큼 다시 저장해야 한다는 뜻은 아니다.

그렇게 하면 GQA의 Memory Advantage가 사라진다.

136. 혼동하기 쉬운 부분 — KV Cache 절감률

\[h_Q=64, \quad h_{KV}=8\]

이면 GQA Cache는 MHA의

\[\boxed{ 12.5\% }\]

즉

\[\boxed{ 87.5\% }\]

가 줄어든다.

두 표현을 혼동하지 않는다.

137. 혼동하기 쉬운 부분 — Batch 8배

KV Cache가 1/8이 되었다고 전체 Serving VRAM 사용량까지 1/8이 되는 것은 아니다.

따라서 최대 Batch Size가 반드시 정확히 8배가 된다고 단정하지 않는다.

138. 혼동하기 쉬운 부분 — FlashAttention

FlashAttention은 Dense Attention의 Pairwise Interaction 자체를 일반적으로 선형 개수로 바꾸는 Algorithm이 아니다.

핵심은

\[\boxed{ \text{IO-aware exact attention} }\]

과 Intermediate Materialization 감소다.

139. 혼동하기 쉬운 부분 — MLA

MLA의 핵심을 이해할 때

\[\boxed{ \text{low-dimensional latent KV representation} }\]

에 집중한다.

원자료의 “고유값 분해” 표현을 실제 Eigen-Decomposition Algorithm으로 받아들이지 않는다.

140. 전체 Attention Flow

하나의 Head에서는

\[\boxed{ X \rightarrow Q,K,V }\]

를 만든다.

그다음

\[\boxed{ Q,K \rightarrow QK^T }\]

Scaling과 Mask를 적용한다.

\[\boxed{ QK^T \rightarrow \frac{QK^T}{\sqrt{d_k}}+M }\]

141. Weight Generation

다음으로

\[\boxed{ \frac{QK^T}{\sqrt{d_k}}+M \rightarrow \operatorname{Softmax} \rightarrow A }\]

142. Information Aggregation

마지막으로

\[\boxed{ A,V \rightarrow AV }\]

즉

\[\boxed{ \text{compare} \rightarrow \text{normalize} \rightarrow \text{aggregate} }\]

143. Multi-Head Flow

MHA에서는 이 Attention을 여러 Head에서 병렬 수행한다.

\[\boxed{ \text{Head}_1, \dots, \text{Head}_h }\]

를 계산하고

\[\boxed{ \operatorname{Concat} \rightarrow W_O }\]

를 통해 다시 Model Dimension으로 합친다.

144. GQA Flow

GQA에서는

\[\boxed{ \text{many Q heads} + \text{fewer KV heads} }\]

를 사용한다.

따라서

\[\boxed{ \text{Q diversity 유지} \rightarrow \text{KV sharing} \rightarrow \text{smaller KV cache} }\]

라는 구조를 가진다.

145. LLM Inference 연결

Autoregressive Serving에서는 Sequence가 길어질수록 KV Cache가 증가한다.

따라서

\[\boxed{ \text{MHA} \rightarrow \text{GQA/MQA} \rightarrow \text{reduced KV-cache footprint} }\]

는 현대 LLM Inference Efficiency의 중요한 Architecture 축이다.

146. 정리

Attention은 Query와 Key의 Dot Product를 이용해 Token 간 Compatibility Score를 만들고, Softmax를 통해 Weight를 구한 뒤 Value를 Weighted Sum하는 Mechanism이다.

기본 식은

\[\boxed{ \operatorname{Attention}(Q,K,V) = \operatorname{Softmax} \left( \frac{ QK^T }{ \sqrt{d_k} } + M \right)V }\]

Q, K, V는 입력

\[X\]

에서 Linear Projection으로 생성된다.

\[\boxed{ Q=XW_Q, \qquad K=XW_K, \qquad V=XW_V }\]

Score Element는

\[\boxed{ q_i^Tk_j }\]

이며

\[\boxed{ q_i^Tk_j = \|q_i\| \|k_j\| \cos\theta }\]

따라서 Dot Product는 Direction과 Magnitude를 모두 반영한다.

원자료의 확률 가정 아래에서

\[\boxed{ \mathbb E[ q^Tk ] = 0 }\]

이고

\[\boxed{ \operatorname{Var}( q^Tk ) = d_k }\]

따라서

\[\boxed{ \frac1{\sqrt{d_k}} }\]

를 곱하면

\[\boxed{ \operatorname{Var} \left( \frac{ q^Tk }{ \sqrt{d_k} } \right) = 1 }\]

을 얻는다.

이는 Head Dimension 증가에 따른 Dot-Product Scale 증가를 보정한다.

Multi-Head Attention에서는 여러 개의 독립 Projection을 이용한다.

\[\boxed{ \operatorname{head}_i = \operatorname{Attention} ( XW_Q^{(i)}, XW_K^{(i)}, XW_V^{(i)} ) }\]

이들을 Concatenate한 뒤

\[\boxed{ \operatorname{MHA}(X) = \operatorname{Concat} ( \operatorname{head}_1, \dots, \operatorname{head}_h ) W_O }\]

로 결합한다.

Autoregressive Inference에서는 이전 Token의 Key와 Value를 KV Cache에 저장한다.

MHA에서는

\[\boxed{ h_{KV}=h_Q }\]

이고 MQA에서는

\[\boxed{ h_{KV}=1 }\]

GQA에서는

\[\boxed{ 1<h_{KV}<h_Q }\]

인 중간 구조를 사용할 수 있다.

Group Size는

\[\boxed{ g = \frac{ h_Q }{ h_{KV} } }\]

이고 각 KV Head를 \(g\)개의 Query Head가 공유한다.

따라서 MHA 대비 KV Cache 비율은

\[\boxed{ \frac{ M_{\mathrm{GQA}} }{ M_{\mathrm{MHA}} } = \frac{ h_{KV} }{ h_Q } = \frac1g }\]

예를 들어

\[h_Q=64, \qquad h_{KV}=8\]

이면

\[\boxed{ M_{\mathrm{GQA}} = \frac18 M_{\mathrm{MHA}} }\]

즉 MHA 대비 Cache가 12.5% 남고 87.5% 감소한다.

단 이것이 전체 Serving Memory나 Maximum Batch Size가 정확히 동일한 비율로 변한다는 뜻은 아니다.

원자료의 수치 예제에서는 \(X\)와 \(W_K\)의 Matrix Multiplication에 산술적 불일치가 존재한다.

제시된 Matrix를 그대로 계산하면

\[\boxed{ Q = \begin{bmatrix} 1&0\\ 0&1 \end{bmatrix} }\]
\[\boxed{ K = \begin{bmatrix} 1&1\\ 0&0 \end{bmatrix} }\]
\[\boxed{ V = \begin{bmatrix} 0&1\\ 1&0 \end{bmatrix} }\]

따라서

\[\boxed{ \frac{ QK^T }{ \sqrt2 } \approx \begin{bmatrix} 0.7071&0\\ 0.7071&0 \end{bmatrix} }\]

Autoregressive Causal Mask까지 적용하면

\[\boxed{ A \approx \begin{bmatrix} 1&0\\ 0.6698&0.3302 \end{bmatrix} }\]

이고

\[\boxed{ O \approx \begin{bmatrix} 0&1\\ 0.3302&0.6698 \end{bmatrix} }\]

FlashAttention은 이 Attention 수학식을 바꾸는 Approximation이 아니라, Tile과 Online Softmax를 이용하여 \(S\times S\) Intermediate의 HBM Materialization과 Memory Traffic을 줄이는 방식으로 이해한다.

GQA 이후에는 KV Representation 자체를 저차원 Latent로 압축하는 MLA와 같은 구조로 연결할 수 있다.

따라서 DL-10의 전체 흐름은

\[\boxed{ \text{Linear Projection} \rightarrow Q,K,V \rightarrow \text{Scaled Dot Product} \rightarrow \text{Causal Mask} \rightarrow \text{Softmax} \rightarrow \text{Weighted Value Sum} }\]

Architecture 관점에서는

\[\boxed{ \text{Single Attention} \rightarrow \text{MHA} \rightarrow \text{MQA / GQA} }\]

로 확장된다.

LLM System 관점에서는

\[\boxed{ \text{Attention Architecture} \rightarrow \text{KV Cache} \rightarrow \text{Memory / Bandwidth Cost} \rightarrow \text{Inference Efficiency} }\]

로 연결된다.

147. 정리

Scaled dot-product attention은 \(QK^T/\sqrt{d_k}\)의 유사도를 softmax 가중치로 바꾸고 그 가중치로 \(V\)를 합성한다. MHA는 여러 query·key·value head를 병렬로 두며, GQA는 여러 query head가 더 적은 KV head를 공유해 표현 구조와 KV cache 비용 사이를 조절한다.
