2. 핵심 요약

BERT는 대규모 비라벨 텍스트에서 깊은 양방향(deep bidirectional) 표현을 사전학습한 뒤, 같은 사전학습 모델을 여러 downstream task에 fine-tuning하는 language representation model이다.

기존의 대표적 사전학습 방식은 다음 두 흐름으로 나뉘었다.

  1. Feature-based approach
  • ELMo처럼 사전학습 representation을 downstream의 task-specific architecture에 추가 feature로 사용한다.
  1. Fine-tuning approach
  • OpenAI GPT처럼 사전학습 model parameter 전체를 downstream task에서 함께 fine-tuning한다.

BERT 논문이 지적한 핵심 문제는 기존 language model의 unidirectionality이다. OpenAI GPT의 Transformer는 left-to-right 구조이므로 각 token이 self-attention에서 왼쪽 context만 볼 수 있다. ELMo는 left-to-right LM과 right-to-left LM을 각각 학습한 뒤 두 representation을 연결하지만, 모든 layer에서 양방향 문맥을 공동으로 조건화하는 구조는 아니다.

BERT는 이 제약을 Masked Language Model (MLM) 로 해결한다. 입력 token 일부를 가린 뒤 주변의 왼쪽과 오른쪽 context를 모두 이용해 원래 token을 예측하게 함으로써, Transformer encoder 전체를 깊은 양방향 representation으로 사전학습한다.

또한 문장 간 관계를 학습하기 위해 Next Sentence Prediction (NSP) 을 함께 사용한다.

전체 흐름은 다음과 같다.

\[\boxed{ \text{Unlabeled Text} \rightarrow \text{MLM + NSP Pre-training} \rightarrow \text{Pre-trained BERT} \rightarrow \text{Task-specific Fine-tuning} }\]

논문은 이 방식으로 11개의 NLP task에서 새로운 state-of-the-art 결과를 보고한다.

핵심 수치

---

3. 배경 및 제안

3.1 Language model pre-training

논문은 language model pre-training이 다양한 NLP task의 성능을 향상시켜 왔다고 설명한다.

적용 대상은 크게 두 종류다.

Sentence-level task

문장 전체의 의미나 두 문장 사이의 관계를 판단한다.

예:

  • Natural Language Inference
  • Paraphrasing

Token-level task

각 token 수준에서 세밀한 출력을 만들어야 한다.

예:

  • Named Entity Recognition
  • Question Answering

BERT가 해결하려는 문제는 특히 token-level task에서 양쪽 문맥이 모두 필요한 상황이다.

---

3.2 기존 방법 1 — Feature-based approach

대표적인 예는 ELMo다.

ELMo는

\[\text{Left-to-Right LM}\]

과

\[\text{Right-to-Left LM}\]

을 각각 학습한다.

그 뒤 각 token에 대해 두 방향 representation을 연결한다.

\[h_i = [ \overrightarrow{h_i}; \overleftarrow{h_i} ]\]
위 식은 논문의 설명을 이해하기 위해 단순하게 표현한 것이다.

ELMo의 특징은 사전학습 model을 downstream task의 전체 backbone으로 직접 fine-tuning하는 것이 아니라, 사전학습 representation을 task-specific architecture의 feature로 추가한다는 점이다.

논문은 이를 shallow concatenation of independently trained left-to-right and right-to-left LMs라고 대비한다. 논문은 feature-based 접근의 실용적 장점도 두 가지 제시한다. 첫째, 모든 NLP task를 Transformer encoder 구조로 쉽게 표현할 수 있는 것은 아니므로 task-specific architecture가 필요한 경우 pre-trained representation을 feature로 사용할 수 있다. 둘째, 계산 비용이 큰 BERT representation을 학습 데이터에 대해 한 번 미리 계산해 두면, 그 위의 비교적 저렴한 모델로 여러 실험을 반복해 compute cost를 크게 줄일 수 있다.

---

3.3 기존 방법 2 — Fine-tuning approach

대표적인 예는 OpenAI GPT다.

GPT는 사전학습 Transformer를 downstream task에 가져와 전체 parameter를 fine-tuning한다.

하지만 pre-training에서는 left-to-right language model을 사용한다.

따라서 위치 \(i\)의 token은

\[x_1,\ldots,x_{i-1}\]

만 참고할 수 있고 오른쪽의 미래 token은 볼 수 없다.

논문은 이 구조가 sentence-level task에 최적이 아니며, 특히 question answering처럼 각 token의 표현에 양쪽 context가 필요한 task에서는 큰 제약이 될 수 있다고 주장한다.

---

3.4 BERT가 제안한 해결책

BERT의 핵심 제안은 두 가지다.

1. Deep bidirectional Transformer

모든 layer에서 각 token이 왼쪽과 오른쪽 context를 함께 이용한다.

\[\boxed{ \text{Left Context} \leftrightarrow \text{Token} \leftrightarrow \text{Right Context} }\]

2. 새로운 pre-training task

기존 left-to-right LM 대신 다음 두 task를 사용한다.

  1. Masked Language Model
  2. Next Sentence Prediction

이 두 task를 통해 BERT는 bidirectional representation과 text-pair representation을 함께 사전학습한다.

---

3.5 논문이 제시한 기여

논문이 직접 정리한 기여는 다음과 같다.

  1. Bidirectional pre-training의 중요성을 보인다.
  • OpenAI GPT의 unidirectional pre-training과 구별된다.
  • ELMo의 독립적인 LTR·RTL representation 결합과도 구별된다.
  1. 대규모 task-specific architecture 설계의 필요성을 줄인다.
  • 같은 BERT backbone에 최소한의 output layer만 추가해 sentence-level과 token-level task를 처리한다.
  1. 11개 NLP task에서 state-of-the-art 성능을 달성한다.

---

4. 사전 지식

---

5. Architecture

5.1 전체 학습 구조

BERT framework는 두 단계로 구성된다.

Stage 1 — Pre-training

비라벨 데이터로 두 개의 unsupervised task를 학습한다.

\[\boxed{ \text{Masked LM} + \text{Next Sentence Prediction} }\]

Stage 2 — Fine-tuning

사전학습 parameter로 BERT를 초기화한 뒤, 각 downstream task의 labeled data로 모든 parameter를 end-to-end fine-tuning한다.

각 downstream task는 동일한 pre-trained checkpoint에서 시작하지만, 이후에는 각각 별도의 fine-tuned model이 된다.

그림 삽입 위치 — Figure 1 왼쪽에는 MLM과 NSP를 사용하는 BERT pre-training을, 오른쪽에는 MNLI·NER·SQuAD 등 서로 다른 task가 같은 pre-trained BERT에서 fine-tuning되는 구조를 배치한다. 논문의 핵심은 output layer를 제외하면 pre-training과 fine-tuning에서 거의 같은 architecture를 사용한다는 점이다.

---

5.2 Transformer Encoder

BERT architecture는 원래 Transformer 구현을 기반으로 한 multi-layer bidirectional Transformer encoder다.

논문은 다음 기호를 사용한다.

두 대표 모델은 다음과 같다.

FFN/filter size는 모든 설정에서

\[4H\]

로 둔다.

BERTBASE는 OpenAI GPT와 model size를 가능한 한 비슷하게 맞춰 비교하도록 설계됐다.

---

5.3 BERT와 GPT의 attention 차이

논문이 강조하는 핵심 구조적 차이는 attention masking이다.

OpenAI GPT

각 token은 왼쪽 context만 본다.

\[x_i \leftarrow x_1,\ldots,x_i\]

즉 causal 또는 left-to-right attention이다.

BERT

각 token은 전체 sequence의 왼쪽과 오른쪽 context를 모두 참고한다.

\[x_i \leftarrow x_1,\ldots,x_{i-1},x_i,x_{i+1},\ldots,x_n\]

단, 이렇게 그대로 language modeling을 하면 target token 자체를 볼 수 있으므로 정답을 쉽게 복사할 수 있다.

BERT는 이를 해결하기 위해 예측 대상 token을 가리는 MLM을 사용한다.

쉽게 이해하기 GPT의 pre-training에서는 현재 위치가 뒤의 단어를 보지 못하도록 막는다. BERT에서는 뒤의 단어까지 볼 수 있게 두되, 맞혀야 할 단어 자체를 숨겨 놓는다.

---

5.4 Input Representation

BERT는 하나의 input format으로

  • single text
  • text pair

를 모두 표현할 수 있도록 설계한다.

논문에서 `"sentence"`는 반드시 문법적인 한 문장을 뜻하지 않는다. 연속된 임의의 text span일 수 있다.

`"sequence"`는 BERT에 실제로 입력되는 token sequence를 의미하며, 하나 또는 두 개의 text span을 포함할 수 있다.

---

5.5 WordPiece Tokenization

BERT는 30,000개 vocabulary의 WordPiece embedding을 사용한다.

논문의 Figure 2 예시에서는

`playing`

과 같은 단어가

`play` + `##ing`

처럼 subword로 표현될 수 있다.

---

5.6 [CLS]와 [SEP]

[CLS]

모든 sequence의 가장 앞에 추가한다.

\[[\mathrm{CLS}], x_1,x_2,\ldots\]

마지막 BERT layer에서 [CLS] 위치의 hidden vector를

\[C\in\mathbb{R}^{H}\]

로 표기하며, classification task의 aggregate sequence representation으로 사용한다.

[SEP]

두 text span을 구분한다.

예:

\[[\mathrm{CLS}] \quad \text{Sentence A} \quad [\mathrm{SEP}] \quad \text{Sentence B} \quad [\mathrm{SEP}]\]

---

5.7 Token + Segment + Position Embedding

각 token의 최종 input representation은 세 embedding의 합이다.

\[E_i = E_i^{\text{token}} + E_i^{\text{segment}} + E_i^{\text{position}}\]
위 식은 Figure 2의 구조를 수식으로 정리한 것이다.

Token Embedding

해당 WordPiece token의 lexical representation이다.

Segment Embedding

token이 sentence A에 속하는지 sentence B에 속하는지 표시한다.

\[E_A \quad\text{or}\quad E_B\]

Position Embedding

sequence에서 token의 위치를 나타낸다.

그림 삽입 위치 — Figure 2 `[CLS] my dog is cute [SEP] he likes play ##ing [SEP]` 예시를 사용해 Token Embedding + Segment Embedding + Position Embedding을 더하는 구조를 재구성한다.

---

5.8 Pre-training Task #1 — Masked Language Model

표준 left-to-right LM 대신 입력 token 일부를 무작위로 선택해 원래 token을 예측한다.

논문에서는 전체 WordPiece token 중

\[15\%\]

를 prediction target으로 선택한다.

예:

`my dog is hairy`

에서 `hairy`가 target으로 선택되었다고 하자.

모델은 주변 문맥을 이용해 원래 token을 예측한다.

\[\text{my dog is [MASK]} \rightarrow \text{hairy}\]

MLM의 output은 선택된 위치의 final hidden vector를 vocabulary softmax에 넣어 원래 vocabulary ID를 맞히는 방식이다.

BERT는 denoising auto-encoder처럼 전체 입력을 복원하는 것이 아니라 선택된 masked token만 예측한다.

---

5.9 왜 일반 양방향 Language Model을 그대로 쓰지 않는가

일반적인 conditional LM에서 모든 token이 양쪽 context를 볼 수 있게 하면, 여러 layer를 거치는 동안 예측 대상 단어가 자기 자신을 간접적으로 볼 수 있다.

그러면 model은 정답을 쉽게 복사할 수 있다.

따라서 BERT는

\[\text{target token을 가리고}\]
\[\text{나머지 양쪽 context를 사용해 예측}\]

하도록 만든다.

이 방식이 deep bidirectional representation을 학습할 수 있게 한다.

---

5.10 80% / 10% / 10% Masking Strategy

항상 `[MASK]`로 바꾸면 문제가 생긴다.

Pre-training 중에는 `[MASK]`를 많이 보지만 실제 fine-tuning 입력에는 `[MASK]`가 나타나지 않기 때문이다.

이를 줄이기 위해 prediction target으로 선택된 15% token에 다음 규칙을 적용한다.

예를 들어 `hairy`가 target이면 다음과 같이 된다.

세 경우 모두 model이 예측해야 하는 정답은 원래 token인 `hairy`다.

실제 전체 token 기준

Prediction target은 전체 token의 15%이므로 대략

  • `[MASK]`: \(0.15\times0.8=12\%\)
  • Random replacement: \(0.15\times0.1=1.5\%\)
  • Unchanged prediction target: \(0.15\times0.1=1.5\%\)

가 된다.

---

5.11 MLM을 통한 Bidirectional Context

예를 들어 다음 입력을 생각한다.

`the man went to [MASK] store`

`[MASK]` 위치의 representation은 왼쪽의

`the man went to`

뿐 아니라 오른쪽의

`store`

도 동시에 활용한다.

따라서 MLM은

\[P(x_i\mid x_{<i},x_{>i})\]

형태의 문맥을 이용해 target token을 예측한다고 이해할 수 있다.

이 확률식은 논문의 MLM 절차를 이해하기 위한 표현이며, 논문에 번호가 붙은 원식은 아니다.

---

5.12 Pre-training Task #2 — Next Sentence Prediction

QA나 NLI 같은 task는 두 text span 사이의 관계를 이해해야 한다.

논문은 이를 사전학습하기 위해 binary Next Sentence Prediction을 사용한다.

두 text span A와 B를 선택할 때:

NSP에서는 최종 `[CLS]` representation \(C\)를 사용한다.

논문은 최종 model의 NSP accuracy가 97–98%라고 보고한다.

논문의 예시

IsNext

`[CLS] the man went to [MASK] store [SEP]` `he bought a gallon [MASK] milk [SEP]`

NotNext

`[CLS] the man [MASK] to the store [SEP]` `penguin [MASK] are flight ##less birds [SEP]`

5.13 MLM + NSP의 공동 학습

BERT pre-training loss는

  • Masked LM likelihood
  • Next Sentence Prediction likelihood

의 평균을 합친다.

개념적으로는 다음처럼 볼 수 있다.

\[\mathcal{L}_{\text{BERT}} = \mathcal{L}_{\text{MLM}} + \mathcal{L}_{\text{NSP}}\]
위 식은 논문의 설명을 간단히 정리한 표기다.

5.15 Pre-training Input 생성

각 training input을 만들 때 corpus에서 두 text span을 뽑는다.

첫 번째 span은 A embedding, 두 번째 span은 B embedding을 받는다.

두 span의 합친 길이는

\[\leq512\text{ tokens}\]

가 되도록 한다.

NSP를 위해 두 번째 span은

  • 50% 실제 다음 span
  • 50% random span

으로 만든다.

그 뒤 WordPiece tokenization을 적용하고 전체 token의 15%를 MLM target으로 선택한다.

5.19 Fine-tuning

Fine-tuning에서는 pre-trained BERT parameter를 초기값으로 사용하고 downstream task의 labeled data로 전체 parameter를 업데이트한다.

5.21 Classification Task

Sentence classification이나 sentence-pair classification에서는 `[CLS]`의 final hidden vector

\[C\in\mathbb{R}^{H}\]

를 사용한다.

Label 수가 \(K\)일 때 새로운 classification weight는

\[W\in\mathbb{R}^{K\times H}\]

이다.

논문은 GLUE fine-tuning에서 classification loss를 다음 형태로 설명한다.

\[\log(\operatorname{softmax}(CW^\top))\]

BERT backbone의 모든 parameter와 classification layer를 함께 fine-tuning한다.

5.23 Token-level Task

NER나 QA처럼 token별 output이 필요한 task에서는 각 token의 final representation

\[T_i\in\mathbb{R}^{H}\]

를 사용한다.

즉 BERT는 같은 backbone으로

  • sequence-level representation: \(C\)
  • token-level representation: \(T_i\)

를 모두 제공한다.

5.24 SQuAD Question Answering

Question과 passage를 하나의 packed sequence로 입력한다.

  • Question: segment A
  • Passage: segment B

Fine-tuning에서 새로 추가하는 주요 parameter는

\[S\in\mathbb{R}^{H}, \qquad E\in\mathbb{R}^{H}\]

두 vector다.

각 token \(T_i\)가 answer의 시작점일 score는

\[S\cdot T_i\]

끝점일 score는

\[E\cdot T_i\]

로 계산한다.

시작 확률은 전체 passage token에 대한 softmax로 구한다.

\[P_i = \frac{e^{S\cdot T_i}} {\sum_j e^{S\cdot T_j}}\]

Candidate answer span \((i,j)\)의 score는

\[S\cdot T_i + E\cdot T_j\]

이고

\[j\geq i\]

인 span 중 score가 가장 큰 것을 선택한다.

---

5.25 SQuAD v2.0의 No-answer 처리

SQuAD v2.0은 passage에 정답이 없을 수도 있다.

BERT는 answer가 없는 경우

\[[\mathrm{CLS}]\]

위치를 start와 end로 취급한다.

No-answer score는

\[s_{\text{null}} = S\cdot C + E\cdot C\]

로 계산하고, 가장 좋은 non-null span score와 비교한다. 가장 높은 non-null span score는 다음과 같다.

\[\hat{s}_{i,j} = \max_{j\geq i} \left(S\cdot T_i+E\cdot T_j\right)\]

BERT는 다음 조건을 만족할 때 answer가 존재한다고 예측한다.

\[\hat{s}_{i,j} > s_{\text{null}}+\tau\]

임계값 \(\tau\)는 SQuAD v2.0의 dev set에서 F1 점수가 최대가 되도록 선택한다. 이 조건을 만족하지 않으면 no-answer로 판정한다.

5.26 SWAG

SWAG는 네 개의 possible continuation 중 가장 자연스러운 것을 선택하는 task다.

각 후보마다

\[[\mathrm{CLS}] \; \text{Sentence A} \; [\mathrm{SEP}] \; \text{Candidate B} \; [\mathrm{SEP}]\]

sequence를 만든다.

각 candidate의 `[CLS]` representation에 task-specific vector를 적용해 score를 계산하고, 네 후보 score에 softmax를 적용한다.

6.6 Ablation — Pre-training Task의 효과

BERTBASE와 같은 architecture를 사용하되 pre-training task를 변경해 비교한다.

No NSP

MLM은 유지하지만 NSP를 제거한다.

논문은 NSP 제거가 특히

  • QNLI
  • MNLI
  • SQuAD

성능을 떨어뜨렸다고 보고한다.

LTR & No NSP

MLM 대신 OpenAI GPT와 비슷한 left-to-right LM을 사용하고 NSP도 제거한다.

이 model은 비교한 모든 task에서 MLM 기반 bidirectional model보다 낮은 성능을 보이며, 특히 MRPC와 SQuAD에서 큰 차이가 난다.

+ BiLSTM

LTR model 위에 fine-tuning 단계에서 random initialization BiLSTM을 추가한다.

SQuAD는 개선되지만 pre-trained bidirectional BERT에는 크게 미치지 못하고, GLUE task에서는 오히려 성능이 저하된다.

---

6.7 왜 Deep Bidirectionality가 중요한가

논문은 LTR과 RTL model을 따로 학습한 뒤 concat하는 ELMo 방식도 고려한다.

그러나 다음 이유를 제시한다.

  1. 두 개의 model을 학습하므로 단일 bidirectional model보다 약 두 배 비싸다.
  2. QA 같은 task에서는 RTL model이 question을 조건으로 answer representation을 만들기 어렵다.
  3. 모든 layer에서 왼쪽·오른쪽 context를 함께 사용하는 deep bidirectional model보다 표현력이 제한된다.

---

6.8 Ablation — Model Size

논문은 layer 수, hidden size, attention head 수를 바꾸며 model size 효과를 측정한다.

Model size가 커질수록 네 dataset 모두에서 accuracy가 지속적으로 개선된다.

논문은 MRPC처럼 labeled example이 약 3,600개뿐인 작은 dataset에서도 충분한 pre-training이 이루어졌다면 큰 model이 이점을 보였다고 강조한다.

---

6.9 Feature-based BERT

BERT 논문의 주요 결과는 전체 parameter를 fine-tuning하는 방식이지만, feature-based 방식도 CoNLL-2003 NER에서 실험한다.

BERT parameter를 고정하고 한 개 또는 여러 layer의 activation을 feature로 추출한 뒤 BiLSTM classifier에 넣는다.

가장 좋은 feature-based 방식인 top four hidden layer concatenation은 full fine-tuning보다 Dev F1이 0.3 낮았다.

논문은 이를 통해 BERT가 fine-tuning과 feature-based 접근 모두에 효과적임을 보인다.

7.3 BERT와 OpenAI GPT 비교에서 논문이 강조한 점

BERT Appendix는 OpenAI GPT를 가장 직접적으로 비교 가능한 기존 pre-training method로 본다.

두 모델의 차이는 architecture 이름 자체보다 pre-training에서 정보가 흐르는 방식에 있다.

\[\text{GPT} : \quad \boxed{\text{Left-to-Right Transformer}}\]
\[\text{BERT} : \quad \boxed{\text{Bidirectional Transformer + MLM}}\]

BERTBASE는 GPT와 model size를 비슷하게 설계했고, 논문은 ablation을 통해 성능 차이의 대부분이 bidirectionality와 두 pre-training task에서 나온다고 주장한다.

다만 논문은 완전히 동일한 조건은 아니라고 명시한다.

따라서 논문은 이러한 차이를 인정하면서도, Section 5.1 ablation을 근거로 핵심 개선이 bidirectionality와 MLM/NSP pre-training에서 비롯된다고 해석한다.

---

7.4 한 문장 정리

\[\boxed{ \text{BERT} = \text{Transformer Encoder} + \text{Deep Bidirectional Self-Attention} + \text{MLM} + \text{NSP} + \text{Full Fine-tuning} }\]

BERT 논문의 핵심은 Transformer encoder가 왼쪽과 오른쪽 context를 모든 layer에서 함께 이용하도록 사전학습하고, 같은 pre-trained backbone을 최소한의 task-specific 변경만으로 다양한 NLP task에 fine-tuning할 수 있음을 보인 것이다.
