연구 요약 및 목표

제약·바이오 분야의 체계적 문헌고찰과 의료 근거 합성에 활용되는 LLM 기반 문헌 분석을 대상으로 한다.

임상논문의 수치가 집계 단위·치료군·분석 단계·환자 공유 관계와 정확하게 연결되는지 평가한다.

치과 분할구강·안과 양안 비교시험의 표·각주·본문을 연결하고, 근거 검색 누락과 수치·단위 해석 오류를 구분하는 것이 목표다.

연구 배경 및 케이스

  • 임상 수치 추출에서 잘못된 항목 배정에 따른 수치 귀속 오류를 확인함.
  • 분할구강·양안 비교시험에서는 환자 수와 신체 부위 수를 구분하고, 치료군 간 환자 공유 관계를 파악할 필요 있음.
  • 모집·배정·최종 분석 단계와 결과별 시점에 맞춰 표본 수를 연결함.

선행연구에서 보고한 실제 오류 사례를 임상시험 문헌·진료기록·검사 PDF·음성으로 구분해 정리함.

이 사례들은 수치와 지표·집단·좌우·시점의 연결을 확인할 필요성을 보여줌. 고유 환자 수 중복 합산과 환자·눈·치아 수 혼동의 발생 여부는 이번 평가 자료에서 별도로 검증할 대상임.

평가 데이터셋 구축 계획

1) 공개 임상시험 원문 직접 수집 — Yun·TrialMind 참고

PubMed에서 분할구강·양안 비교시험 문헌을 검색하고, PMC Open Access Subset의 원문을 확보한다.

수집 형식은 제공 가능한 JATS XML·PDF·보충자료다. PMC OA Web Service로 제공 파일과 재이용 조건을 확인하고 PMID·PMCID·DOI와 연결해 보관한다. 01 · Yun, 03 · TrialMind의 공개 전문 활용 방식을 참고한다.

2) 체계적 문헌고찰에서 포함 연구 추적 — URCA·수치 추론 연구 참고

Cochrane Library 등에서 관련 리뷰를 찾고, 포함 문헌 목록을 따라 접근 가능한 개별 연구 원문을 확보한다.

수집 형식은 리뷰·개별 논문의 PDF 또는 제공되는 XML·HTML, 제공되는 경우의 SVG forest plot이다. 리뷰–연구–복수 보고서 연결을 기록하며 원문·SVG의 제공 여부는 자료별로 확인한다. 02 · URCA, 05 · 수치 추론 연구를 참고한다.

3) 논문과 임상시험 등록자료 연결 — LEADS 참고

PMC 원문과 ClinicalTrials.gov API의 시험 레코드를 PMID·NCT ID로 연결한다.

원문은 XML·PDF, 등록자료는 API JSON으로 확보한다. 공개된 LEADSInstruct의 과제별 JSON 자료를 확보한다. 04 · LEADS의 논문–등록자료 연결 방식을 참고한다.

4) 기존 공개 벤치마크 확보 — Yun·TrialMind 참고

Yun 평가 데이터에서 주석 CSV·JSON과 초록·결과 절 XML을, TrialReviewBench에서 리뷰 CSV·검색/선별 JSONL·추출 과제별 파일을 확보하는 경로다.

기존 과제의 비교·재현 자료로 활용하며 자체 치과·안과 문헌 평가 자료와 구분한다.

실험 설계 및 파이프라인 구성

문헌 수집

1) 자체 문헌 평가 자료 구성

3절의 1)~3) 수집 경로에서 치과·안과 원문을 확보한다. 원본과 출처·식별자를 함께 보관하고 동일 시험의 복수 보고서를 묶는다. 표 유형·원문 형식·환자 내 배정 여부를 기록해 구성 편중을 확인한다.

2) 기존 벤치마크 비교 자료 구성

3절의 4) 공개 자료는 원래의 과제 정의와 분할을 유지해 별도 비교군으로 둔다. 자체 문헌과의 중복 및 학습·평가 자료의 중복을 확인한다. 자체 자료는 동일 임상시험의 보고서·표·질문을 한 묶음으로 분할한다.

문서 구조 정리

1) JATS XML → Markdown — 선행연구 방식

XML의 절·문단·표·캡션·각주를 읽고 스타일 속성을 정리한 뒤 Markdown으로 변환한다. 01 · Yun의 초록·결과 절 입력과 03 · TrialMind의 전문 입력을 비교한다. XML도 변환 후 구조가 보존됐는지 원문과 대조한다.

2) 텍스트 PDF → 텍스트·좌표 기반 표 — 선행연구 방식

07 · Zaidi의 pdfplumber·PyMuPDF 텍스트 추출을 참고한다. 페이지·표 위치를 함께 보관하고 표 추출 결과의 행·열·머리글 연결을 확인한다. 스캔 PDF에는 OCR을 적용하고 텍스트 PDF와 구분해 평가한다.

3) 레이아웃·표 구조 인식 파서 — 비교 방법

Docling과 MinerU로 문서를 변환하고 구조화 결과에서 표·셀·본문 연결을 구성한다. 파서 버전·OCR 여부·표 인식 설정을 기록한다.

4) 기존 파서 + 구조 보정 코드 — 비교 방법

다단 머리글의 상하 관계, 병합 셀의 적용 범위, 각주 기호와 설명, 페이지에 걸친 표의 연결을 보정한다. 원문 숫자와 위치를 유지하며 변경 내역을 저장한다.

기존 출력·자동 보정 출력·사람이 원문 구조만 교정한 출력을 비교한다. 환자 수를 임의 계산하거나 정답 귀속을 추가하는 처리는 구조 복원과 분리한다.

5) 정보 범위와 표현 형식 분리 — 비교 변수

본문·표·각주 중 무엇을 제공하는지, 구조가 얼마나 보존되는지, 같은 구조를 Markdown·HTML·JSON 중 어떤 형식으로 전달하는지를 별도 변수로 둔다.

05 · 수치 추론 연구의 본문·표 분리 비교를 참고해 정보 범위의 영향을 측정한다.

근거 구성·검색

1) 검색 없이 전문 제공 — TrialMind·수치 추론 연구 참고

관련 본문·표·각주 전체를 모델에 제공하는 기준선이다. 입력 한도를 넘으면 잘린 범위와 누락 근거를 기록한다. 검색을 사용하지 않는 조건도 원문 근거는 제공한다. 03 · TrialMind, 05 · 수치 추론 연구를 참고한다.

2) 일반 밀집 검색 RAG — OphthoACR 참고

문서를 청크로 분할하고 임베딩 유사도로 관련 근거를 검색한다. 08 · OphthoACR의 FAISS 검색과 512토큰·100토큰 중첩을 비교 설정으로 사용한다. 문헌·표·시점 등의 메타데이터를 함께 유지한다.

3) 출처별 균등 검색·질의 중심 군집화 — URCA 참고

같은 시험의 여러 보고 논문에서 근거를 고르게 검색한 뒤 UMAP·GMM 군집화와 질문 관련 근거 추출을 적용한다. 일반 RAG에서 균등 검색과 군집화를 각각 추가·제거해 효과를 확인한다. 02 · URCA의 방법이며 별도 리랭커를 사용한 실험은 아니다.

4) 주변 문맥 확장·리랭킹 — 비교 방법

검색된 셀·청크에 머리글·캡션·각주·관련 문단을 붙인다. BM25·밀집 검색·혼합 검색과 리랭커 적용 여부를 비교한다.

한 번에 여러 요소를 바꾸지 않고 각각의 추가 효과를 비교한다.

5) 정답 근거 제공 — 진단 비교

사람이 주석한 충분한 근거 구간을 제공하되 정답 값·귀속 라벨은 별도로 주지 않는다. 검색 결과와 비교해 근거 누락의 영향을 확인한다. 실제 배포 조건과 구분하고 입력 근거가 충분해도 남는 추출 오류를 분석한다.

구조화 추출

1) 과제·필드 정의 후 JSON 또는 YAML 출력 — Yun·LEADS 참고

질문에 치료 비교·결과 지표·목표 시점을 명시하고 자료형이 정해진 필드를 추출한다. 01 · Yun의 군별 사건 수·표본 수 또는 평균·표준편차·표본 수와 04 · LEADS의 군 ID·단위·시점·분모 항목을 출력 필드로 구성한다. 환자 공유 관계를 포함한 출력과 비교한다.

2) 상세 지시·스키마 제약 비교 — 안과 검사 PDF 연구 참고

07 · Zaidi의 상세 프롬프트와 JSON Schema 조건을 참고한다. 본 연구에서는 프롬프트 내용과 출력 제약을 가능한 한 따로 비교하고 값 정확도와 형식 준수율을 분리한다. 원 연구는 프롬프트·출력 제약·후처리가 함께 달라 스키마 하나의 효과로 해석하지 않는다.

3) 근거 추출 → 수치 추출 → 검증·계산 — TrialMind·수치 추론 연구 참고

문단·표·셀에 출처 ID를 부여하고 답과 함께 원문 문구·위치를 연결한다. JSON·YAML을 파싱해 키·자료형·결측·필드 간 일관성을 검사한다. 통계량 변환이나 효과량 계산은 별도 단계로 두고 원문 값과 계산값을 구분한다. 03 · TrialMind, 05 · 수치 추론 연구를 참고한다.

4) 기본 모델 ↔ 지도학습 모델 — LEADS·수치 추론 연구 참고

학습 가능한 동일 모델에서 학습 전후를 비교한다. 정답만 학습하는 SFT와 원문 근거·짧은 설명을 포함하는 SFT를 비교한다. 공개 가중치 모델에는 LoRA·QLoRA를 적용한다. API 모델의 학습 가능 여부는 모델별로 확인한다. 04 · LEADS, 05 · 수치 추론 연구를 참고한다.

5) 수치·귀속 보상 학습 — 학습 비교

05 · 수치 추론 연구의 GRPO·필드별 수치 보상을 참고한다. 수치 정답 보상과 단위·군·시점 귀속을 포함하는 보상을 비교한다.

같은 시작 체크포인트에서 비교하고 보상 가중치·학습 순서는 개발 자료에서 정한다.

평가·오류 분석

1) 원문 독립 주석·합의 정답 — Yun·안과 연구 참고

문항별 수치·귀속 관계와 근거 위치를 원문에서 주석하고 독립 검토와 불일치 합의 절차를 둔다. 모호·미기재·원문 내 충돌을 구분하고 근거 없이 정답을 보충하지 않는다. 01 · Yun, 07 · Zaidi의 원문 대조·합의를 참고한다.

2) 리뷰·등록자료에서 정답 자료 확보 — TrialMind·LEADS 참고

리뷰의 특성 표·forest plot 또는 등록자료에서 정답 자료를 구성한 뒤 원문과 대조한다. 03 · TrialMind, 04 · LEADS를 참고하며, 등록자료와 논문이 다를 때 등록값을 그대로 정답으로 확정하지 않는다. 자동 채점과 수동 검수 결과를 구분한다.

3) 필드·문항·귀속 관계별 채점 — 평가 지표

개별 필드 일치율, 필수 필드 전체 일치율(EM), JSON·YAML 형식 준수율을 나누어 측정한다. 수치와 단위·군·시점·환자 공유 관계의 동시 일치율을 평가한다.

01 · Yun, 04 · LEADS, 07 · Zaidi를 참고한다.

4) 파싱·검색·추출 오류 분리 — 진단 비교

원문 → 변환 문서 → 검색 근거 → 모델 출력을 순서대로 대조한다. 구조 교정 입력과 정답 근거 입력으로 정보가 손실된 단계를 확인하고 여러 원인이 겹친 사례도 기록한다.

원문 구조가 깨졌는데 추론 실패로만 분류하거나, 검색에서 빠진 값을 환각과 동일하게 취급하지 않는다.

5) 오류 유형별 사례 분석 — 9편의 오류 검토 참고

누락·원문 없는 값 생성·군/지표/집단/시점 오귀속·비율/건수 혼동·좌우/치아/부위 혼동·형식 오류를 원문과 대조한다. 2절의 실제 사례를 분류의 출발점으로 삼되 음성 전사 오류와 임상시험 문헌 추출 오류는 별도로 집계한다. 고유 환자 수 중복 합산은 자체 자료에서 발생 여부를 확인한다.

6) 요소 제거·반복 실행·결론 영향 — URCA·수치 추론·안과 연구 참고
