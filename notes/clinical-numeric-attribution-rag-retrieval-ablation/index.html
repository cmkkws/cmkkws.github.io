문서 구조 요소별 9종 어블레이션 설계

JATS XML 구조 파서가 생성하는 각 요소가 LLM 수치 귀속 정확도와 토큰 소모에 미치는 영향을 분리 측정하기 위해 **단계적 누적 5종(L0L4)**과 **단일 요소 제거 4종(LOO-1LOO-4)**을 설계했다.

개발 93편 실측 토큰 통계 (`tiktoken: cl100k_base`)

1차 개발 후보 93편 전체(parsed-dev-93/papers/PMID*.json, 대·소목차 역할 분류 결과 포함)를 9개 직렬화 버전으로 변환해 실제 BPE 토크나이저(tiktoken cl100k_base)로 토큰 수를 계측했다.

  • 공통 포함 범위: 논문 제목(title) + 초록(abstract·trans-abstract) + 본문(body) + 별도 표·그림 영역(floats-group)
  • 공통 제외 범위: 참고문헌·사사 목록(back)은 9종 비교에서 모두 제외하고, 별도 참고 행으로 원문 부하를 측정했다.
  • 문맥 한도 기준: 순수 입력 텍스트 기준 4K(4,096), 8K(8,192), 16K(16,384), 40K(40,960) 초과 편수를 집계했다. (추론 시 출력 예약 1,024 + 64토큰을 제외하면 안전 한계는 더 낮아진다.)

1) 단계적 기능 ON (L0 → L4) 토큰 분포

2) 풀 구조(L4)에서 단일 옵션 OFF (LOO-1 ~ LOO-4) 변화

3) L4-Compact 이중 ID 경량화 실측 및 참고 비교군

L4의 정보와 추적성을 유지하면서 프롬프트 토큰을 줄이기 위해 **저장·채점 DB용 전역 ID(PMID...:경로)**와 **LLM 프롬프트 입력용 단축 ID(D1·[p1]·[t1] + 표 내부 [r,c] + 열·행 헤더 역인덱스 1회 선언)**를 분리하는 이중 매핑(L4-Compact)을 구현해 검증했다.

  • 무손실 역복원 검증: 93편 총 20,367개 표 셀에서 (r, c) 좌표 충돌 0건, 역인덱스 헤더 복원 불일치 **0건**으로 원본 전역 node_id 100% 복원 확인.
  • 실제 서버 여유 한계: L4-Compact 최장 논문 1위(PMID 41893183: 48,088토큰)와 2위(PMID 37430291: 29,853토큰)의 격차가 커서 32K(32,768)·38K·40K(40,960) 어느 기준에서도 **40K 초과 편수는 93편 중 단 1편(PMID 41893183)**으로 동일하다.

계측 결과 해석, 이중 ID 설계 근거 및 RAG 3원칙

1) 실측 수치에서 확인된 핵심 결과

  1. 기본 서버(4K/8K)에서는 L0조차 전문 투입 불가: 가장 가벼운 평면 마크다운(L0)도 93편 중 86편(92.5%)이 4K를 초과하고 33편(35.5%)이 8K를 초과한다. L4-Compact 역시 4K 초과 91편, 8K 초과 62편으로 기본 서버에서는 RAG 청킹이 필수다.
  2. 오른쪽 꼬리 역설 및 로컬 40K 초과 14편 → 1편: L0 → L4 증가폭이 평균 3.49배인데 P90에서는 5.77배(10,490 → 60,529)로 뛰어, 표가 크고 복잡한 핵심 임상 논문일수록 40K 상한에 먼저 걸려 잘리는(14/93편) 역설이 있었다. L4-Compact는 이를 평균 -52.2%(12,220토큰)·P90 -68.1%(19,287토큰)로 줄여 노드 ID를 끈 LOO-4(평균 14,234)보다도 가볍고 92/93편(98.9%)이 32K·40K 이내로 들어온다.
  3. 토큰 주범은 node_id(44.3%)와 headers(29.9%), 가성비 최강은 notes·<xref>(합 2.6%): 표 각주(notes)와 본문 <xref>·배정 연결은 합쳐도 평균 **~679토큰(2.6%)**만 쓰므로 항상 유지한다.
  4. 40K 전문 vs 4K~8K RAG 역할 분리 (어텐션 희석 및 실험 변별력): 입력 \(N\)이 4K에서 32K~40K로 늘면 Softmax 확률 총합(\(1\)) 안에서 무관한 배경 문장·타 시점 표로 어텐션이 분산되고(Lost-in-the-Middle), 유사 오답 표와의 혼동이 커지며 Prefill(\(O(N^2)\))·KV 캐시 부담도 급증한다. 또한 30K~40K로 예산을 풀면 L4-Compact(평균 12,220) 기준 검색기 성능과 무관하게 전문이 통째로 들어가 검색·청킹 모듈의 변별력이 사라진다. 따라서 40K 전문은 No-Retrieval 상한 기준선, 4K~8K RAG는 고밀도 근거 선별 파이프라인으로 역할을 분리한다.

2) 타 도메인 선행연구 기반 L4-Compact 이중 ID 설계 근거

  • 저장 DB vs 프롬프트 입력 분리 (ALCE · LongCite · WebArena · SpreadsheetLLM): RAG 인용 벤치마크(ALCE, LongCite)와 웹 DOM 에이전트(WebArena)처럼 원문 전역 경로(PMID...:1/4/2/0/1, DOM XPath와 동일 구조)는 저장소에 두고 프롬프트에는 짧은 순번([p1], [t1])만 노출해 양방향 딕셔너리로 역복원한다. 표 내부는 SpreadsheetLLM(arXiv:2407.09025)의 역인덱스 압축처럼 셀별 중복 대신 열·행 단위 헤더 범위를 1회만 선언한다.
  • 대안 포맷(LTEM·중첩 트리 JSON·상대 경로 문자열) 대신 채택한 이유: LTEM(확장 마크다운)은 L0(평면 .md) vs 구조 보존 비교 축을 흐리며, 중첩 트리 JSON은 표 형태마다 깊이가 달라져 [r,c] ↔ 원본 node_id 1:1 역추적이 끊긴다. 반면 [p1]/[t1] + [r,c] + 열·행 헤더 역인덱스는 parse_jats.py의 2차원 cells 출력과 100% 무손실로 맞물린다.

구조적 청킹, 표 317개 실측 분포 및 검색기 비교 설계

1) 개발 93편 내 표(table-wrap) 317개 크기 분포와 Small-to-Big 청킹

RAG의 **4K~8K 한도는 청크 1개 크기가 아니라 검색된 근거 청크들의 합(Total Token Budget)**이다. 개발 93편의 모든 표(317개)를 L4-Compact 기준으로 계측한 결과, 일반 표는 4K~8K 예산에 문단과 함께 들어가지만 극소수 초대형 표가 별도 분할 규칙을 요구한다.

  • 최대 단일 표 사례: PMID 31752813 Table 7(47행, 12,541토큰), PMID 35103799 Table 1(20행, 9,026토큰), PMID 36339386 Table 3(50행, 8,980토큰) 등 3개 표는 표 1개만으로 8K를 초과한다.
  • 검색용 인덱스 vs LLM 본체 분리 (Small-to-Big): 표는 수치(td)가 많아 임베딩 모델(512토큰 상한 등)에 통째로 넣으면 뒷행·각주가 잘리거나 숫자 잡음에 신호가 희석된다. 따라서 **검색 인덱스는 절 제목 + 표 캡션 + 다단 머리글 + 각주 + 문자 셀(150~400토큰)**로 작게 색인하고, 검색에 당첨된 표만 **L4-Compact 표 본체(중앙 1,191토큰)**를 꺼내 LLM에 전달한다.
  • 거대 표 행 분할 Fallback: 단일 표가 단일 청크 상한(예: 3K) 또는 잔여 토큰 예산을 초과하면 임의 문자 절단 대신 행(row) 블록 단위로 쪼개되, 각 조각 상단에 다단 열 머리글과 하단에 표 각주를 자동 복제해 문맥 훼손을 방지한다.

2) 검색기 비교 설계: 어휘(BM25) vs 범용 SOTA(Qwen3-Embedding) vs 도메인 특화(MedCPT)

BM25 단독, 임베딩 단독, 그리고 BM25 + 임베딩 RRF 하이브리드를 동일 청크·동일 토큰 예산 하에서 비교한다. 특히 어휘 검색을 BM25가 담당하므로, 밀집(Dense) 임베딩 축에서는 기존 BGE-M3 단일안 대신 범용 최신 SOTA와 의생명 도메인 특화 모델 2종을 정면 대조한다.

  • 공정 비교 통제: MedCPT의 512토큰 한계(기존 PubMedBERT와 동일)에서 뒷부분 절단이 발생하지 않도록, 문단 청크(200~450토큰)와 표 검색 인덱스(150~400토큰)를 두 모델에 동일하게 입력한다.

3) RAG 공정 비교와 토큰 통제 3원칙

  • 실측 토큰 및 절삭률 동시 보고: 정확도(All-fields EM)만 비교하지 않고 실제 입력 토큰 수, 토큰당 정확도, 문맥 상한 초과로 인한 절삭 건수를 함께 기록한다.
  • 표현 형식(L0~L4·L4-Compact)과 청킹 전략 분리: 동일 근거 구간(또는 오라클 스팬)에서 구조 포맷 효과를 먼저 분리 측정하고, 고정 길이(Fixed-size) 대비 계층 구조(Structural) 청킹의 표·각주 경계 보존 효과는 별도 축으로 비교한다.
  • Top-K 개수 대신 총 토큰 예산(Total Token Budget) 고정: 같은 Top-K=5 청크라도 L0과 L4의 토큰 부피가 수배 차이 나므로, 동일 토크나이저 기준 총 토큰 상한(4K / 8K)과 중복 노드 제거를 적용해 입력 정보량 편향을 차단한다.
