PS-03 — Law of Total Probability & Bayes Theorem

전확률 정리와 베이즈 정리를 분할 사건, 주변화, 사후확률의 관점에서 전개한다.

  • #Partition

개념

전확률 정리와 Bayes 정리가 필요한 이유확률 문제에서는 어떤 사건 \(A\)의 확률을 직접 계산하기 어려운 경우가 많다.

이때 가능한 원인이나 상황을 \(B_1,B_2,\dots,B_k\) 로 나누고 각 상황에서의 조건부 확률을 계산하면 전체 확률을 복원할 수 있다.

이것이 Law of Total Probability의 핵심이다.

반대 방향의 문제반대로 어떤 결과 \(A\)가 실제로 관측되었다고 하자.

우리는

이 결과가 관측되었다면 원인 \(B_i\)가 실제로 발생했을 가능성은 얼마나 되는가?

를 알고 싶을 수 있다.

이때 사용하는 것이 Bayes' Theorem이다.

두 정리의 핵심 흐름전확률 정리:

\[\boxed{ \text{원인별 확률} \rightarrow \text{전체 결과 확률} }\]

Bayes 정리:

\[\boxed{ \text{관측된 결과} \rightarrow \text{원인에 대한 확률 갱신} }\]

원자료 역시 전확률 정리를 weighted marginalization, Bayes 정리를 관측으로부터 가설의 확률을 수정하는 도구로 설명한다.

표기·차원

Sample Space표본공간을 \(\boxed{ \Omega }\) 라고 하자.

\(\Omega\)는 확률 실험에서 가능한 모든 Outcome을 포함한다.

Partition of Sample Space사건들의 집합 \(\boxed{ \{B_1,\dots,B_k\} }\) 가 \(\Omega\)를 Partition한다는 것은 기본적으로 다음 두 구조적 조건을 의미한다.

첫째,

\[\boxed{ B_i\cap B_j = \varnothing \qquad (i\neq j) }\]

즉 서로 배타적이다.

둘째,

\[\boxed{ \bigcup_{i=1}^{k} B_i = \Omega }\]

즉 모든 가능성을 빠짐없이 포함한다.

Partition의 핵심은 집합론적 조건원자료는 Partition 조건에

\[P(B_i)>0\]

까지 포함한다.

하지만 Partition 자체의 집합론적 정의에는 Positive Probability가 필수 조건이 아니다.

즉 어떤 \(B_i\)가

\[P(B_i)=0\]

이어도 집합론적으로는 Partition의 원소가 될 수 있다.

\(P(B_i)>0\)가 필요한 이유다만

\[P(A\mid B_i) = \frac{ P(A\cap B_i) }{ P(B_i) }\]

라는 elementary conditional-probability definition을 직접 사용하려면

\[\boxed{ P(B_i)>0 }\]

이어야 한다.

따라서 유한형 전확률 정리를

\[P(A) = \sum_iP(A\mid B_i)P(B_i)\]

형태로 쓸 때는 보통 Positive-Probability Partition을 가정하거나 Zero-Probability Cell을 별도로 처리한다.

Mutually Exclusive

\[B_i\cap B_j=\varnothing\]

이라는 것은 한 Outcome이 서로 다른 두 Cell에 동시에 속하지 않는다는 뜻이다.

핵심 연산

출발점 — Conditional ProbabilityBayes 정리는 새로운 독립적인 확률 공리가 아니다.

기본적으로 Conditional Probability 정의에서 나온다.

\[\boxed{ P(A\mid B) = \frac{ P(A\cap B) }{ P(B) } }\]

단,

\[\boxed{ P(B)>0 }\]

이어야 한다.

Product Rule위 식을 정리하면

\[\boxed{ P(A\cap B) = P(A\mid B)P(B) }\]

마찬가지로

\[\boxed{ P(A\cap B) = P(B\mid A)P(A) }\]

따라서

\[\boxed{ P(A\mid B)P(B) = P(B\mid A)P(A) }\]

라는 관계가 나온다.

Exhaustive

\[\bigcup_iB_i=\Omega\]

라는 것은 모든 Outcome이 적어도 하나의 Cell에 속한다는 뜻이다.

Partition의 결과따라서 각 Outcome은 정확히 하나의 \(B_i\) 에 속한다.

이 성질이 전확률 정리의 핵심이다.

임의의 사건 \(A\)이제 \(A\subseteq\Omega\) 를 임의의 사건이라고 하자.

Partition을 사용하면

\[A = A\cap\Omega\]

Partition 대입

\[\Omega = \bigcup_{i=1}^{k}B_i\]

이므로

\[A = A\cap \left( \bigcup_{i=1}^{k}B_i \right)\]

Distributive Law교집합과 합집합의 분배법칙으로

\[\boxed{ A = \bigcup_{i=1}^{k} ( A\cap B_i ) }\]

\(A\cap B_i\)들도 서로 배타적\(i\neq j\)이면

\[B_i\cap B_j = \varnothing\]

따라서 \((A\cap B_i) \cap (A\cap B_j)\)

\[= A\cap B_i\cap B_j = \varnothing\]

Additivity 적용서로 배타적인 사건들의 합집합이므로 Probability Additivity에 의해

\[\boxed{ P(A) = \sum_{i=1}^{k} P(A\cap B_i) }\]

Product Rule 대입각 항은 다음과 같다.

\[P(A\cap B_i) = P(A\mid B_i)P(B_i)\]

따라서

\[\boxed{ P(A) = \sum_{i=1}^{k} P(A\mid B_i)P(B_i) }\]

이것이 Law of Total Probability다. 원자료의 증명도 같은 분해를 사용한다.

전확률 정리의 직관각 \(P(A\mid B_i)\) 는 상황 \(B_i\) 안에서 \(A\)가 얼마나 자주 발생하는지를 나타낸다.

그러나 각 상황의 발생 빈도는 서로 다를 수 있다.

따라서 \(P(B_i)\) 를 Weight로 사용해 평균을 내야 한다.

Weighted Average

\[P(A) = \sum_i P(A\mid B_i)P(B_i)\]

에서

\[\sum_iP(B_i)=1\]

이므로 \(P(A)\)는 조건부 확률들의 Weighted Average로 볼 수 있다.

BoundsWeighted Average이므로

\[\boxed{ \min_iP(A\mid B_i) \le P(A) \le \max_iP(A\mid B_i) }\]

Binary Partition특히 \(B,\quad B^c\) 는 \(\Omega\)의 Partition을 이룬다.

따라서

\[\boxed{ P(A) = P(A\mid B)P(B) + P(A\mid B^c)P(B^c) }\]

실전 문제에서 매우 자주 사용한다.

Bayes Theorem의 출발점Conditional Probability 정의를 다시 쓰자.

\[\boxed{ P(B_k\mid A) = \frac{ P(B_k\cap A) }{ P(A) } }\]

단,

\[\boxed{ P(A)>0 }\]

교집합 대칭성

\[B_k\cap A = A\cap B_k\]

이므로

\[P(B_k\cap A) = P(A\cap B_k)\]

Product Rule

\[P(A\cap B_k) = P(A\mid B_k)P(B_k)\]

이므로

\[\boxed{ P(B_k\mid A) = \frac{ P(A\mid B_k)P(B_k) }{ P(A) } }\]

전확률 정리 대입Partition \(B_1,\dots,B_k\) 에 대해

\[P(A) = \sum_{i=1}^{k} P(A\mid B_i)P(B_i)\]

따라서

\[\boxed{ P(B_k\mid A) = \frac{ P(A\mid B_k)P(B_k) }{ \sum_{i=1}^{k} P(A\mid B_i)P(B_i) } }\]

이것이 Partition 형태의 Bayes Theorem이다.

Bayes 정리의 가장 단순한 형태두 사건 \(A,B\)에 대해

\[\boxed{ P(B\mid A) = \frac{ P(A\mid B)P(B) }{ P(A) } }\]

방향을 뒤집는다는 의미일반적으로 \(P(A\mid B) \neq P(B\mid A)\) Bayes 정리는 두 조건부 확률을 연결하지만 단순히 순서를 뒤집는 것이 아니다.

반드시 Prior와 Evidence가 함께 들어간다.

Prior\(\boxed{ P(B) }\) 는 관측 \(A\)를 보기 전 \(B\)에 대한 Probability다.

이를 Prior Probability라고 부른다.

Likelihood\(\boxed{ P(A\mid B) }\) 는 \(B\)가 주어졌을 때 \(A\)가 관측될 Probability다.

Bayesian parameter inference에서는 관측 데이터를 고정하고 Parameter의 함수로 볼 때 이를 Likelihood라고 부른다.

Evidence\(\boxed{ P(A) }\) 는 관측 \(A\)가 전체적으로 나타날 Probability다.

이를

  • Evidence
  • Marginal Likelihood

라고 부를 수 있다.

Posterior\(\boxed{ P(B\mid A) }\) 는 \(A\)를 관측한 뒤 \(B\)에 대해 갱신된 Probability다.

이를 Posterior Probability라고 한다.

원자료 역시 이 네 용어를 같은 구조로 정리한다.

Bayes의 구조따라서

\[\boxed{ \text{Posterior} = \frac{ \text{Likelihood}\times\text{Prior} }{ \text{Evidence} } }\]

Proportional Form관측 \(A\)가 고정되어 있으면 Evidence \(P(A)\)는 가설 \(B\)에 따라 변하지 않는다.

따라서

\[\boxed{ P(B\mid A) \propto P(A\mid B)P(B) }\]

라고 쓸 수 있다.

Normalization의 역할Likelihood × Prior 자체는 여러 가설에 대한 합이 1이라는 보장이 없다.

Evidence가

\[\boxed{ \sum_i P(A\mid B_i)P(B_i) }\]

로 이를 Normalize한다.

Posterior 합따라서 Partition 전체에 대해

\[\boxed{ \sum_i P(B_i\mid A) = 1 }\]

핵심 식 — Partition

\[\boxed{ B_i\cap B_j = \varnothing \qquad i\neq j }\]
\[\boxed{ \bigcup_iB_i = \Omega }\]

핵심 식 — Continuous Bayes

\[\boxed{ p(\theta\mid x) = \frac{ p(x\mid\theta)p(\theta) }{ \int p(x\mid\theta') p(\theta') d\theta' } }\]

핵심 식 — Posterior Proportionality

\[\boxed{ p(\theta\mid x) \propto p(x\mid\theta)p(\theta) }\]

핵심 식 — Posterior Odds

\[\boxed{ \frac{ P(B_1\mid A) }{ P(B_2\mid A) } = \frac{ P(A\mid B_1) }{ P(A\mid B_2) } \frac{ P(B_1) }{ P(B_2) } }\]

핵심 식 — RAG Marginalization

\[\boxed{ P(y\mid x) = \sum_z P(y\mid x,z) P(z\mid x) }\]

핵심 식 — Latent Variable Evidence

\[\boxed{ p(x) = \int p(x\mid z)p(z)\,dz }\]

핵심 식 — Gaussian Prior

\[\boxed{ -\log p(\theta) = \frac{ 1 }{ 2\sigma_0^2 } \|\theta\|_2^2 + C }\]

성질·유도

Posterior Odds두 가설 \(B_1,B_2\)에 대해

\[\frac{ P(B_1\mid A) }{ P(B_2\mid A) } = \frac{ P(A\mid B_1) }{ P(A\mid B_2) } \frac{ P(B_1) }{ P(B_2) }\]

Odds Interpretation즉

\[\boxed{ \text{Posterior odds} = \text{Likelihood ratio} \times \text{Prior odds} }\]

Bayesian update를 이해하는 매우 중요한 식이다.

Bayes Factor두 가설에 대한

\[\boxed{ \frac{ P(A\mid B_1) }{ P(A\mid B_2) } }\]

를 단순한 이산 설정에서 Evidence가 두 가설을 상대적으로 얼마나 지지하는지 나타내는 Likelihood Ratio로 볼 수 있다.

Bayesian model comparison에서는 관련 개념으로 Bayes Factor가 사용된다.

Prior가 사라지는 것이 아니다Likelihood가 크다고 해서 Posterior가 반드시 가장 큰 것은 아니다.

Bayes 정리에서는 Prior도 함께 작용한다.

Base Rate 효과어떤 가설이 매우 희귀하면 높은 \(P(A\mid B)\) 를 가져도 Posterior가 생각보다 낮을 수 있다.

이것이 Base Rate를 무시하면 안 되는 이유다.

Continuous Bayesian Inference이제 Parameter \(\theta\in\Theta\) 가 Continuous하다고 하자.

Probability Mass 대신 Density를 사용한다.

Continuous Bayes Rule관측 \(x\)에 대해

\[\boxed{ p(\theta\mid x) = \frac{ p(x\mid\theta)p(\theta) }{ p(x) } }\]

Continuous EvidenceEvidence는 Parameter를 Marginalize하여

\[\boxed{ p(x) = \int_{\Theta} p(x\mid\theta') p(\theta') \,d\theta' }\]

전체 식따라서

\[\boxed{ p(\theta\mid x) = \frac{ p(x\mid\theta)p(\theta) }{ \int_{\Theta} p(x\mid\theta') p(\theta') \,d\theta' } }\]

원자료의 연속형 확장과 동일하다.

Probability와 Density 구분Continuous Variable에서는 일반적으로

\[P(\theta=a)=0\]

따라서 \(p(\theta\mid x)\) 는 Point Probability가 아니라 Probability Density다.

Density는 1보다 클 수 있다Probability Density는 특정 Point에서

\[p(\theta)>1\]

일 수도 있다.

Probability는 Density를 적분하여 얻는다.

Evidence는 Normalizing ConstantPosterior가 Density가 되려면

\[\int p(\theta\mid x) \,d\theta = 1\]

이어야 한다.

Evidence \(p(x)\)가 바로 이 Normalization을 수행한다.

Joint Distribution 관점Bayes Rule의 핵심은 다음과 같다.

\[\boxed{ p(x,\theta) = p(x\mid\theta)p(\theta) = p(\theta\mid x)p(x) }\]

즉 동일한 Joint Distribution을 두 방향으로 Factorize한 것이다.

MarginalizationJoint Distribution에서 한 Variable을 제거하면 Marginal Distribution을 얻는다.

Discrete Case:

\[\boxed{ P(A) = \sum_i P(A,B_i) }\]

Continuous Case:

\[\boxed{ p(x) = \int p(x,z)\,dz }\]

전확률 정리와 Marginalization따라서 Law of Total Probability는 더 일반적으로 \(\boxed{ \text{marginalization} }\) 의 이산형 표현으로 볼 수 있다.

Conditional Expectation과의 유사 구조전확률 정리는 평균의 Law of Total Expectation과 구조적으로 유사하다.

\[\boxed{ \mathbb E[X] = \mathbb E[ \mathbb E[X\mid Y] ] }\]

Probability 자체도 Indicator Variable의 Expectation으로 보면 같은 구조가 나타난다.

Indicator 해석사건 \(A\)의 Indicator를 \(\mathbf1_A\) 라 하면

\[P(A) = \mathbb E[\mathbf1_A]\]

Conditional Expectation 적용분할 \(\{B_i\}_{i=1}^n\)이 생성하는 정보에 조건화하면 전기댓값 정리로 다음을 얻는다.

\[\mathbb E[\mathbf1_A] = \mathbb E[\mathbb E[\mathbf1_A\mid\sigma(B_1,\dots,B_n)]] = \sum_{i=1}^{n}P(A\mid B_i)P(B_i)\]

L2 Penalty따라서 Gaussian Prior 아래 MAP는 Sum NLL에

\[\boxed{ \frac{\lambda}{2} \|\theta\|_2^2 }\]

형태의 L2 Penalty를 추가한 Objective와 연결된다.

Sum-NLL Convention에서는

\[\boxed{ \lambda = \frac1{\sigma_0^2} }\]

로 대응시킬 수 있다.

원자료도 같은 전개를 제시한다.

Mean Loss Convention 주의만약 NLL을 Sum이 아니라

\[\boxed{ \frac1N \sum_i -\log p(y_i\mid x_i,\theta) }\]

처럼 Mean으로 정의한다면 Regularization Coefficient의 수치 대응도 달라진다.

즉 \(\lambda\) 의 정확한 Scale은 Objective Convention에 의존한다.

L2 Regularization과 Gaussian Prior따라서 다음 연결은 정확하다.

\[\boxed{ \text{isotropic Gaussian prior} \leftrightarrow \text{L2-type MAP penalty} }\]

그러나 Weight Decay와는 구분원자료는 이를 L2 Weight Decay와 완벽하게 동치라고 표현한다.

이 표현은 Optimizer까지 포함하면 지나치게 강하다.

SGD에서의 관계Plain SGD와 같은 특정 Update에서는 Objective에

\[\frac{\lambda}{2}\|\theta\|_2^2\]

를 넣으면 Gradient에 \(\lambda\theta\) 가 추가된다.

이것이 Parameter Shrinkage와 직접 연결된다.

Adaptive Optimizer에서는 주의Adam과 같은 Adaptive Optimization에서는

  • L2 penalty를 Loss에 넣는 방식
  • parameter를 직접 decay하는 방식

이 동일한 Update를 일반적으로 만들지 않는다.

AdamWAdamW는 Weight Decay를 Gradient-based L2 Penalty와 분리하여 적용하는 decoupled weight decay를 사용한다.

따라서

\[\boxed{ \text{Gaussian MAP} \leftrightarrow \text{L2 penalty} }\]

는 정확한 연결이지만,

\[\boxed{ \text{Gaussian MAP} \equiv \text{all implementations of weight decay} }\]

라고 일반화해서는 안 된다.

Prior가 Regularization으로 보이는 이유Prior는 Parameter에 대한 Preference를 표현한다.

Zero-mean Gaussian Prior는 큰 \(\|\theta\|_2\) 에 낮은 Probability Density를 부여한다.

따라서 MAP에서 큰 Parameter Norm에 Penalty를 주는 효과가 생긴다.

MAP와 MLEMaximum Likelihood Estimation은 다음과 같다.

\[\boxed{ \theta_{\mathrm{MLE}} = \arg\max_\theta p(D\mid\theta) }\]

MAP는 여기에 Prior를 포함한다.

\[\boxed{ \theta_{\mathrm{MAP}} = \arg\max_\theta p(D\mid\theta)p(\theta) }\]

Uniform PriorParameter Domain에서 Prior가 Constant인 적절한 상황이라면

\[\boxed{ \theta_{\mathrm{MAP}} = \theta_{\mathrm{MLE}} }\]

가 될 수 있다.

Posterior Distribution과 MAP의 차이Bayesian inference 전체는 \(\boxed{ p(\theta\mid D) }\) 라는 Distribution을 다룬다.

MAP는 그 Distribution의 Mode 하나만 선택한다.

따라서

\[\boxed{ \text{MAP} \neq \text{full Bayesian inference} }\]

Bayes Theorem 자체는 인과 추론 정리가 아니다원자료는 Bayes Rule을 “결과에서 원인을 역추론”하는 틀로 설명한다.

직관적으로 유용하지만 Bayes Rule 자체는 \(\boxed{ \text{causality theorem} }\) 은 아니다.

혼동하기 쉬운 부분 — PartitionPartition의 집합론적 정의 자체는

\[P(B_i)>0\]

를 요구하지 않는다.

Positive Probability는 elementary conditional probability \(P(A\mid B_i)\) 를 정의할 때 필요한 조건이다.

혼동하기 쉬운 부분 — \(P(A\mid B)\)와 \(P(B\mid A)\)일반적으로 \(\boxed{ P(A\mid B) \neq P(B\mid A) }\) 둘을 단순히 뒤집으면 안 된다.

혼동하기 쉬운 부분 — LikelihoodLikelihood \(p(x\mid\theta)\) 는 관측 \(x\)를 고정하고 Parameter \(\theta\)의 함수로 해석한다.

Posterior Density \(p(\theta\mid x)\) 와 동일하지 않다.

혼동하기 쉬운 부분 — EvidenceEvidence \(p(x)\) 는 Posterior를 Normalize한다.

MAP에서 \(\theta\)에 대해 Optimization할 때는 Constant라서 제거할 수 있지만 Bayesian Model Comparison에서는 중요할 수 있다.

혼동하기 쉬운 부분 — Bayes와 CausalityBayes Theorem은 Conditional Probability 관계다.

Posterior가 높다고 해서 Causation이 자동으로 성립하지 않는다.

혼동하기 쉬운 부분 — Continuous ProbabilityContinuous Setting에서는 Density와 Probability를 구분해야 한다.

Point Density 값 자체가 Event Probability는 아니다.

혼동하기 쉬운 부분 — VAE ComplexityVAE의 Evidence가 일반적으로 Intractable할 수 있다는 설명은 맞지만 \(\boxed{ O(e^d) }\) 라는 Complexity가 모든 VAE에 보편적으로 적용되는 것은 아니다.

혼동하기 쉬운 부분 — RAG Retriever\(P(z\mid x)\) 는 Conditional Retrieval Distribution이다.

반드시 Bayesian posterior라는 뜻은 아니다.

혼동하기 쉬운 부분 — RAG의 Top-\(K\)이론적 Marginalization과 실제 Top-\(K\) Retrieval 계산은 구분해야 한다.

실제 시스템은 전체 Document Space를 정확히 합산하지 않을 수 있다.

혼동하기 쉬운 부분 — Gaussian Prior와 L2Gaussian Prior를 사용한 MAP는 L2-penalized Objective와 직접 연결된다.

하지만 모든 Optimizer의 “Weight Decay” 구현과 동일한 Update를 만든다는 뜻은 아니다.

혼동하기 쉬운 부분 — AdamWAdamW의 Decoupled Weight Decay는 Loss에 단순 L2 Penalty를 추가하는 것과 일반적으로 동일하지 않다.

따라서

\[\boxed{ \text{Gaussian prior} \leftrightarrow \text{L2-type MAP regularization} }\]

로 표현하는 것이 정확하다.

혼동하기 쉬운 부분 — MAP와 Full Bayesian InferenceMAP는 Posterior 전체를 유지하지 않는다.

\(\boxed{ \theta_{\mathrm{MAP}} }\) 이라는 Point Estimate 하나를 선택한다.

Law of Total Probability와 Bayes Theorem은 Conditional Probability 위에 세워진 핵심 확률 추론 도구다.

표본공간 \(\Omega\)가 \(B_1,\dots,B_k\) 로 Partition되어 있다고 하자.

Partition의 핵심 조건은

\[\boxed{ B_i\cap B_j=\varnothing \quad(i\neq j) }\]

와

\[\boxed{ \bigcup_iB_i=\Omega }\]

\(P(A\mid B_i)\)를 elementary definition으로 사용하려면 해당 Cell에 대해

\[P(B_i)>0\]

가 필요하다.

사건 \(A\)는

\[A = \bigcup_i (A\cap B_i)\]

로 분해되므로

\[\boxed{ P(A) = \sum_i P(A\cap B_i) }\]

Product Rule

\[P(A\cap B_i) = P(A\mid B_i)P(B_i)\]

를 대입하면

\[\boxed{ P(A) = \sum_i P(A\mid B_i)P(B_i) }\]

가 된다.

이것이 Law of Total Probability다.

Bayes Theorem은

\[\boxed{ P(B_k\mid A) = \frac{ P(A\mid B_k)P(B_k) }{ P(A) } }\]

이고, 전확률 정리를 분모에 대입하면

\[\boxed{ P(B_k\mid A) = \frac{ P(A\mid B_k)P(B_k) }{ \sum_i P(A\mid B_i)P(B_i) } }\]

가 된다.

이를

\[\boxed{ \text{Posterior} = \frac{ \text{Likelihood}\times\text{Prior} }{ \text{Evidence} } }\]

로 기억할 수 있다.

Continuous Parameter에서는 다음과 같다.

\[\boxed{ p(\theta\mid x) = \frac{ p(x\mid\theta)p(\theta) }{ \int p(x\mid\theta') p(\theta') d\theta' } }\]

원자료의 Numerical Example에서는

\[P(B_1)=0.50, \quad P(B_2)=0.30, \quad P(B_3)=0.20\]

이고

\[P(A\mid B_1)=0.80, \quad P(A\mid B_2)=0.20, \quad P(A\mid B_3)=0.05\]

따라서

\[\boxed{ P(A) = 0.8(0.5) + 0.2(0.3) + 0.05(0.2) = 0.47 }\]

Posterior는

\[\boxed{ P(B_1\mid A) = \frac{0.40}{0.47} = \frac{40}{47} \approx 0.8511 }\]
\[\boxed{ P(B_2\mid A) = \frac{0.06}{0.47} = \frac6{47} \approx 0.1277 }\]
\[\boxed{ P(B_3\mid A) = \frac{0.01}{0.47} = \frac1{47} \approx 0.0213 }\]

이며 합은 정확히 1이다.

RAG에서는 Latent Document \(z\)를 주변화하여

\[\boxed{ P(y\mid x) = \sum_z P(y\mid x,z)P(z\mid x) }\]

와 같은 구조를 사용할 수 있다.

이것은 Law of Total Probability 또는 Marginalization의 직접적인 형태다.

다만 실제 RAG에서는 전체 Corpus가 아닌 Top-\(K\) Candidate를 사용하는 경우가 있으므로 이론적 전체 합과 구현을 구분해야 한다.

또한 \(P(z\mid x)\) 는 일반적으로 Conditional Retrieval Distribution이며 반드시 Bayesian Posterior라고 부를 필요는 없다.

VAE와 같은 Latent Variable Model에서는

\[\boxed{ p(x) = \int p(x\mid z)p(z)dz }\]

이고

\[\boxed{ p(z\mid x) = \frac{ p(x\mid z)p(z) }{ p(x) } }\]

Neural Latent Model에서는 이 Posterior 또는 Evidence가 Analytically Intractable할 수 있어 \(\boxed{ q_\phi(z\mid x) }\) 를 사용하는 Variational Inference와 ELBO Optimization으로 이어진다.

이때 계산이 어렵다는 설명은 맞지만 일반적으로 정확한 복잡도를 항상 \(O(e^d)\) 라고 표현할 수는 없다.

MAP에서는

\[\boxed{ p(\theta\mid D) \propto p(D\mid\theta)p(\theta) }\]

이므로

\[\boxed{ \theta_{\mathrm{MAP}} = \arg\max_\theta [ \log p(D\mid\theta) + \log p(\theta) ] }\]

Zero-mean Isotropic Gaussian Prior

\[\theta \sim \mathcal N( 0,\sigma_0^2I )\]

를 가정하면

\[\boxed{ -\log p(\theta) = \frac1{2\sigma_0^2} \|\theta\|_2^2 + C }\]

이므로 MAP는 L2-type Penalized NLL과 연결된다.

그러나 이를 모든 Optimizer에서 구현되는 “Weight Decay”와 완전히 동일하다고 일반화하면 안 된다.

특히 Adaptive Optimizer에서는 L2 Penalty와 Decoupled Weight Decay가 다른 Update를 만들 수 있다.

따라서 PS-03의 전체 핵심 흐름은 다음과 같다.

\[\boxed{ \text{Conditional Probability} \rightarrow \text{Product Rule} \rightarrow \text{Total Probability} \rightarrow \text{Bayes Theorem} }\]

이를 확률모형으로 확장하면

\[\boxed{ \text{Joint Distribution} \rightarrow \text{Marginalization} \rightarrow \text{Posterior Inference} }\]

이고, Machine Learning에서는

\[\boxed{ \text{RAG} \rightarrow \text{latent-document marginalization} }\]
\[\boxed{ \text{VAE} \rightarrow \text{latent posterior inference} }\]
\[\boxed{ \text{MAP} \rightarrow \text{likelihood + prior} }\]

로 연결된다.

예제·적용

Numerical Example 설정원자료의 예제에서는 세 Domain \(B_1,B_2,B_3\) 를 사용한다.

Prior는

\[\boxed{ P(B_1)=0.50 }\]
\[\boxed{ P(B_2)=0.30 }\]
\[\boxed{ P(B_3)=0.20 }\]

Prior 합 검증

\[0.50+0.30+0.20 = 1\]

따라서 Domain들이 Exhaustive하고 Mutually Exclusive하다고 가정하면 Valid Partition Distribution이다.

관측 사건특정 Keyword가 등장하는 사건을 \(\boxed{ A }\) 라고 한다.

Likelihood는

\[\boxed{ P(A\mid B_1)=0.80 }\]
\[\boxed{ P(A\mid B_2)=0.20 }\]
\[\boxed{ P(A\mid B_3)=0.05 }\]

Joint Probability — \(B_1\)

\[\begin{aligned} P(A\cap B_1) &= P(A\mid B_1)P(B_1)\\ &= 0.80(0.50)\\ &= \boxed{ 0.400 } \end{aligned}\]

Joint Probability — \(B_2\)

\[\begin{aligned} P(A\cap B_2) &= 0.20(0.30)\\ &= \boxed{ 0.060 } \end{aligned}\]

Joint Probability — \(B_3\)

\[\begin{aligned} P(A\cap B_3) &= 0.05(0.20)\\ &= \boxed{ 0.010 } \end{aligned}\]

Total Probability따라서

\[\begin{aligned} P(A) &= 0.400 + 0.060 + 0.010\\ &= \boxed{ 0.470 } \end{aligned}\]

즉

\[\boxed{ P(A)=47.0\% }\]

이다. 원자료 계산과 동일하다.

Posterior \(P(B_1\mid A)\)Bayes Rule에 의해

\[P(B_1\mid A) = \frac{ 0.400 }{ 0.470 }\]

따라서

\[\boxed{ P(B_1\mid A) = \frac{40}{47} \approx 0.85106 }\]

즉 약 \(\boxed{ 85.11\% }\)

Prior와 Posterior 비교관측 전:

\[\boxed{ P(B_1)=50\% }\]

관측 후:

\[\boxed{ P(B_1\mid A)\approx85.11\% }\]

관측 \(A\)가 \(B_1\)에서 상대적으로 훨씬 잘 발생하기 때문에 Posterior가 증가했다.

Posterior \(P(B_2\mid A)\)

\[P(B_2\mid A) = \frac{ 0.060 }{ 0.470 }\]

이므로

\[\boxed{ P(B_2\mid A) = \frac6{47} \approx 0.12766 }\]

즉 \(\boxed{ 12.77\% }\)

Posterior \(P(B_3\mid A)\)

\[P(B_3\mid A) = \frac{ 0.010 }{ 0.470 }\]

이므로

\[\boxed{ P(B_3\mid A) = \frac1{47} \approx 0.02128 }\]

즉 약 \(\boxed{ 2.13\% }\)

Posterior 합 검증

\[\frac{40}{47} + \frac6{47} + \frac1{47} = \frac{47}{47} = \boxed{ 1 }\]

원자료의 모든 수치 계산은 정확하다.

이 예제의 Likelihood Ratio\(B_1\)과 \(B_2\)를 비교하면

\[\frac{ P(A\mid B_1) }{ P(A\mid B_2) } = \frac{0.8}{0.2} = 4\]

즉 관측 \(A\)는 \(B_2\)보다 \(B_1\) 아래에서 네 배 더 높은 Probability를 갖는다.

Prior Odds

\[\frac{ P(B_1) }{ P(B_2) } = \frac{0.5}{0.3} = \frac53\]

Posterior Odds따라서

\[\frac{ P(B_1\mid A) }{ P(B_2\mid A) } = 4\cdot\frac53 = \frac{20}{3}\]

실제로

\[\frac{40/47}{6/47} = \frac{20}{3}\]

Bayes Update의 본질이 예제에서 Posterior를 결정하는 것은 단순히 Likelihood만이 아니다.

\[\boxed{ \text{Likelihood} \times \text{Prior} }\]

가 핵심이다.

RAG와 전확률 정리원자료는 RAG를 Latent Document \(z\)에 대한 Marginalization의 예로 연결한다.

Query를 \(x\) 답변을 \(y\) 검색 문서를 \(z\) 라고 하자.

Joint Conditional DistributionChain Rule에 의해

\[\boxed{ P(y,z\mid x) = P(y\mid x,z)P(z\mid x) }\]

Document Marginalization\(z\)를 제거하면

\[\boxed{ P(y\mid x) = \sum_z P(y,z\mid x) }\]

따라서

\[\boxed{ P(y\mid x) = \sum_z P(y\mid x,z) P(z\mid x) }\]

이 식의 의미각 Document \(z\)에 대해 \(P(y\mid x,z)\) 를 계산하고, Retriever가 부여한 \(P(z\mid x)\) 를 Weight로 사용해 합산하는 구조다.

\(P(z\mid x)\) 용어 주의원자료는 \(P(z\mid x)\)를 검색기의 “사후 확률”이라고 부른다.

하지만 일반적인 RAG Retriever의 \(P(z\mid x)\) 는 단순히 query가 주어졌을 때 문서에 대한 조건부 검색 분포로 이해하는 편이 안전하다.

반드시 명시적인 Bayesian Prior × Likelihood 업데이트로 얻어진 Posterior일 필요는 없다.

Generator Probability\(\boxed{ P(y\mid x,z) }\) 는 Query와 Document가 주어졌을 때 Generator가 Output \(y\)에 부여하는 Conditional Probability다.

Parameter inference 문맥이 아니라면 이를 굳이 “Likelihood”라고 부르지 않아도 된다.

실제 Retrieval의 유한 후보이론식은 전체 문서 공간에 대해

\[\sum_z\]

를 사용할 수 있다.

하지만 실제 Retrieval System은 대개 전체 Corpus가 아니라 검색된 Candidate 집합, 예를 들어 Top-\(K\) Document를 사용한다.

따라서 실용적 계산은 전체 Marginalization의 Approximation 또는 Restriction이 될 수 있다.

Weighted Sum이 오류 방지를 보장하는가원자료는 여러 문서를 합산하면 특정 문서의 오류에 종속되지 않고 강인한 생성을 정당화한다고 설명한다.

이는 가능한 장점이지만 확률식 자체가 Robustness를 자동 보장하는 정리는 아니다.

Retriever 및 Generator가 동시에 잘못될 수 있기 때문이다.

RAG에서 확실히 말할 수 있는 것수학적으로 확실한 것은

\[\boxed{ \text{latent document variable를 합산하여 marginalize할 수 있다} }\]

는 점이다.

성능이나 Robustness 개선은 Architecture와 Training에 관한 경험적 문제다.

VAE와 Bayes Rule원자료는 VAE의 Latent Variable를 \(z\) 관측 Data를 \(x\) 로 두고 Bayes Rule과 연결한다.

VAE Generative Model기본적인 Latent Variable Model에서는

\[\boxed{ p_\theta(x,z) = p_\theta(x\mid z)p(z) }\]

와 같이 Joint Distribution을 Factorize한다.

Evidence관측 \(x\)의 Marginal Likelihood는 다음과 같다.

\[\boxed{ p_\theta(x) = \int p_\theta(x\mid z)p(z) \,dz }\]

이는 Continuous Law of Total Probability다.

True PosteriorBayes Rule에 의해

\[\boxed{ p_\theta(z\mid x) = \frac{ p_\theta(x\mid z)p(z) }{ p_\theta(x) } }\]

Evidence 대입

\[\boxed{ p_\theta(z\mid x) = \frac{ p_\theta(x\mid z)p(z) }{ \int p_\theta(x\mid z')p(z') \,dz' } }\]

VAE의 핵심 어려움많은 Neural Latent Variable Model에서는 \(p_\theta(x)\) 또는 \(p_\theta(z\mid x)\) 를 정확하게 계산하기 어렵다.

이것이 Approximate Inference를 사용하는 주요 이유다.

원자료의 \(O(e^d)\) 표현 보완원자료는 고차원 Evidence Integral이 \(O(e^d)\) 의 복잡도를 가져 계산 불가능하다고 서술한다.

하지만 일반적인 VAE Evidence 계산에 대해 \(\boxed{ O(e^d) }\) 라는 하나의 보편적 Complexity를 부여할 수는 없다.

더 정확한 표현정확한 계산 난이도는

  • Model structure
  • Latent dimension
  • Conditional distribution
  • Integral의 analytic tractability

등에 달려 있다.

따라서 핵심은

\[\boxed{ \text{evidence/posterior가 일반적으로 analytically intractable할 수 있다} }\]

는 것이다.

Variational ApproximationVAE에서는 Inference Model \(\boxed{ q_\phi(z\mid x) }\) 를 도입하여 True Posterior \(p_\theta(z\mid x)\) 를 근사한다.

ELBO대표적인 ELBO는 다음과 같다.

\[\boxed{ \log p_\theta(x) \ge \mathbb E_{ q_\phi(z\mid x) } [ \log p_\theta(x\mid z) ] - D_{\mathrm{KL}} \left( q_\phi(z\mid x) \| p(z) \right) }\]

ELBO가 필요한 이유ELBO를 최대화함으로써 직접 계산하기 어려운 \(\log p_\theta(x)\) 를 다루면서 Approximate Posterior \(q_\phi(z\mid x)\)를 학습할 수 있다.

Bayes와 VAE의 연결 핵심따라서 VAE에서 Bayes Rule의 역할은

\[\boxed{ p(z\mid x) \propto p(x\mid z)p(z) }\]

라는 Posterior 구조를 보여주는 데 있다.

MAP Estimation이제 Parameter \(\theta\) 와 Dataset \(D\) 를 생각하자.

Bayes Rule은 다음과 같다.

\[\boxed{ p(\theta\mid D) = \frac{ p(D\mid\theta)p(\theta) }{ p(D) } }\]

MAPMaximum A Posteriori Estimation은 다음과 같다.

\[\boxed{ \theta_{\mathrm{MAP}} = \arg\max_\theta p(\theta\mid D) }\]

Evidence 제거\(p(D)\)는 \(\theta\)에 의존하지 않으므로

\[\theta_{\mathrm{MAP}} = \arg\max_\theta p(D\mid\theta)p(\theta)\]

Log 적용Logarithm은 Strictly Increasing하므로

\[\boxed{ \theta_{\mathrm{MAP}} = \arg\max_\theta \left[ \log p(D\mid\theta) + \log p(\theta) \right] }\]

원자료의 MAP 전개와 동일하다.

iid Dataset Likelihood조건부 독립 구조를 가정하면

\[\boxed{ p(D\mid\theta) = \prod_{i=1}^{N} p(y_i\mid x_i,\theta) }\]

따라서

\[\boxed{ \log p(D\mid\theta) = \sum_{i=1}^{N} \log p(y_i\mid x_i,\theta) }\]

Gaussian PriorParameter에 isotropic zero-mean Gaussian Prior를 가정하자.

\[\boxed{ p(\theta) \propto \exp \left( -\frac{ \|\theta\|_2^2 }{ 2\sigma_0^2 } \right) }\]

Log Prior따라서

\[\boxed{ \log p(\theta) = -\frac{ 1 }{ 2\sigma_0^2 } \|\theta\|_2^2 + C }\]

MAP Objective이를 MAP 식에 넣으면

\[\boxed{ \theta_{\mathrm{MAP}} = \arg\max_\theta \left[ \sum_i \log p(y_i\mid x_i,\theta) - \frac{ 1 }{ 2\sigma_0^2 } \|\theta\|_2^2 \right] }\]

Minimization Form부호를 바꾸면

\[\boxed{ \theta_{\mathrm{MAP}} = \arg\min_\theta \left[ -\sum_i \log p(y_i\mid x_i,\theta) + \frac{ 1 }{ 2\sigma_0^2 } \|\theta\|_2^2 \right] }\]

Hypothesis와 Cause 구분\(B_i\)를 “원인”이라고 부를 수 있는 Application도 있지만, 수학적으로 \(B_i\)는 단지 Event 또는 Hypothesis다.

Bayes Rule은 Conditional Probability 방향을 재표현한다.

Correlation과 Causation\(P(B\mid A)\) 가 높다고 해서

\[B\to A\]

라는 Causal Relation이 자동으로 증명되는 것은 아니다.

Causal Inference에는 추가 구조와 Assumption이 필요하다.

Evidence가 0이면Bayes Rule

\[P(B\mid A) = \frac{ P(A\mid B)P(B) }{ P(A) }\]

을 elementary event-level form으로 사용하려면

\[\boxed{ P(A)>0 }\]

이어야 한다.

Impossible Evidence만약

\[P(A)=0\]

이면 위 Fraction은 정의되지 않는다.

Continuous Probability에서는 Point Event가 Probability 0일 수 있으므로 Density 기반 Conditional Distribution 개념이 필요하다.

Likelihood는 Posterior가 아니다\(p(x\mid\theta)\) 를 \(\theta\)의 함수로 보면 Likelihood다.

하지만 \(\boxed{ p(x\mid\theta) }\) 자체가 \(\theta\)에 대한 Probability Distribution은 아니다.

일반적으로

\[\int p(x\mid\theta)d\theta = 1\]

이어야 할 이유가 없다.

Posterior는 Normalize되어 있다반면 \(p(\theta\mid x)\) 는 \(\theta\)에 대한 Density이므로

\[\boxed{ \int p(\theta\mid x)d\theta = 1 }\]

Evidence의 역할 재확인

\[p(x) = \int p(x\mid\theta)p(\theta)d\theta\]

가 바로 \(p(x\mid\theta)p(\theta)\) 를 Parameter Space에서 Normalize한다.

Log BayesBayes Rule에 Log를 취하면

\[\boxed{ \log p(\theta\mid D) = \log p(D\mid\theta) + \log p(\theta) - \log p(D) }\]

Optimization에서는 이 형태가 매우 중요하다.

Negative Log Form부호를 바꾸면

\[\boxed{ -\log p(\theta\mid D) = -\log p(D\mid\theta) - \log p(\theta) + \log p(D) }\]

즉

\[\boxed{ \text{posterior objective} = \text{data-fit term} + \text{prior penalty} }\]

구조를 얻는다.

LLM Next-Token Modeling과 Bayes 구분Autoregressive LLM은

\[\boxed{ P_\theta( x_{1:T} ) = \prod_{t=1}^{T} P_\theta( x_t\mid x_{<t} ) }\]

와 같은 Conditional Probability Factorization을 사용한다.

이것은 Probability Chain Rule이다.

모든 LLM 식이 Bayes Rule인 것은 아니다원자료의 “LLM과 생성모델의 거의 모든 정형화식이 Bayes inference에 뿌리를 둔다”는 표현은 다소 넓다.

Autoregressive Factorization, Softmax, Cross-Entropy 등은 Bayes Rule 없이도 직접 정의된다.

더 정확한 연결Bayes Rule은 특히

  • Latent-variable inference
  • Bayesian parameter inference
  • MAP
  • probabilistic inversion

에서 직접적으로 중요하다.

반면 일반적인 Next-Token Prediction 자체는 주로 Conditional Probability와 Chain Rule로 설명된다.

RAG에서도 구분RAG의

\[P(y\mid x) = \sum_z P(y\mid x,z)P(z\mid x)\]

는 전확률/주변화 구조다.

반드시 Bayes posterior calculation을 수행하는 식은 아니다.

VAE에서는 Bayes가 직접 등장VAE에서는

\[p(z\mid x) = \frac{ p(x\mid z)p(z) }{ p(x) }\]

가 직접적인 Bayes posterior다.

따라서 RAG보다 Bayes Rule 자체와의 연결이 더 직접적이다.

MAP에서는 Bayes가 직접 등장

\[p(\theta\mid D) \propto p(D\mid\theta)p(\theta)\]

를 최적화하므로 MAP 역시 Bayes Rule의 직접적인 응용이다.

전체 개념 연결먼저 Conditional Probability에서 시작한다.

\[\boxed{ P(A\mid B) = \frac{ P(A\cap B) }{ P(B) } }\]

Product Rule Flow이를 재배열하면

\[\boxed{ P(A\cap B) = P(A\mid B)P(B) }\]

를 얻는다.

Partition Flow표본공간을 \(B_1,\dots,B_k\) 로 Partition하면

\[\boxed{ A = \bigcup_i ( A\cap B_i ) }\]

Total Probability Flow따라서

\[\boxed{ P(A) = \sum_i P(A\mid B_i)P(B_i) }\]

를 얻는다.

Bayes Flow그리고

\[P(B_k\mid A) = \frac{ P(A\mid B_k)P(B_k) }{ P(A) }\]

에 전확률 정리를 대입하여

\[\boxed{ \text{Prior} + \text{Likelihood} \rightarrow \text{Posterior} }\]

를 얻는다.

Latent Variable Flow숨은 Variable \(z\)가 존재하면

\[\boxed{ p(x) = \int p(x\mid z)p(z)dz }\]

로 Marginalize한다.

VAE Flow

\[\boxed{ p(x\mid z)p(z) \rightarrow p(z\mid x) }\]

가 Bayes 구조이고, 실제 계산이 어려운 경우 \(\boxed{ q_\phi(z\mid x) }\) 를 사용하는 Variational Inference로 이어진다.

MAP FlowParameter Inference에서는

\[\boxed{ p(D\mid\theta) p(\theta) \rightarrow p(\theta\mid D) }\]

이며, Posterior Mode를 선택하면 MAP가 된다.

Gaussian-Prior Flow

\[\boxed{ \theta \sim \mathcal N(0,\sigma_0^2I) }\]

이면

\[\boxed{ -\log p(\theta) \propto \|\theta\|_2^2 }\]

따라서

\[\boxed{ \text{Gaussian MAP} \rightarrow \text{L2-type regularized objective} }\]

가 된다.

정리

서로 배타적이고 전체를 덮는 partition \(\{B_i\}\)에 대해 \(P(A)=\sum_iP(A\mid B_i)P(B_i)\)로 원인을 주변화한다. Bayes 정리는 이 joint 관계를 뒤집어 관측 \(A\) 이후의 원인 posterior \(P(B_i\mid A)\)를 계산한다.
