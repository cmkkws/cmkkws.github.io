Phase 목록으로 돌아가기

Learning goal

모델을 만들기 전에, 어느 Python·device에서 실행되는지 확인하고 같은 작은 실험을 반복할 기반을 만든다.

입력·출력 계약

환경 확인 → 연산 → gradient → optimizer update를 구분한다. 같은 seed의 작은 CPU 입력은 같아야 하며, config의 숫자는 모델 shape를 결정한다.

파일 역할

scripts/check_env.py
Python·PyTorch·CUDA 정보를 출력하고 matmul/backward를 실행한다.
src/llm_lab/seed.py
Python·NumPy·PyTorch의 난수 seed와 cuDNN 옵션을 설정한다.
src/llm_lab/config.py
JSON을 ModelConfig로 읽고 기본 FFN 크기를 정한다.
configs/unit.json
테스트에 사용할 작은 모델 설정을 저장한다.
tests/test_p01_init.py
seed 재현과 JSON의 일부 필드 값을 assert로 검사한다.

CUDA를 쓸 수 없으면 CPU 실습은 진행하되 GPU 검증은 미완료로 남긴다.

Follow along

  1. 01

    환경 출력 읽기

    아래 실행 후 Python Executable이 .venv인지 확인한다. CUDA Available에 따라 GPU 또는 CPU 분기가 실행된다. 파일 탐색기의 해당 분기를 읽고 x·y·loss의 관계를 설명한다.

    확인할 결과 · 예상 형태

    Python Executable / PyTorch Version / CUDA Available가 표시된다. 해당 device의 Tensor Matmul & Backward 성공 메시지가 나온다.

  2. 02

    seed와 config 검증

    seed.py와 unit.json을 읽은 뒤 테스트를 실행한다. seed를 두 번 설정해 만든 a·b가 같은지, vocab_size=1000·hidden_dim=64·num_heads=4가 JSON에서 왔는지 확인한다.

    확인할 결과 · 예상 형태

    [PASS] Seed Reproducibility Test Passed. [PASS] ModelConfig JSON Parser Passed: ... 1 passed ...

  3. 03

    backward 다음의 update

    아래 내용을 scripts/smoke_step.py에 저장한다. backward는 gradient를 계산하고 optimizer.step은 parameter 값을 바꾼다. before와 weight를 비교하는 assert가 왜 필요한지 읽는다.

    확인할 결과 · 예상 형태

    다음 단계에서 이 optimizer update 예제를 실행한다.

  4. 04

    CPU·GPU 확인과 기록

    추가 예제를 실행한다. CPU는 항상 검사하고 CUDA를 사용할 수 있을 때 GPU도 검사한다. 실행 명령·버전·device·실패한 assert를 본인의 기록에 남긴다.

    확인할 결과 · 예상 형태

    optimizer step: cpu PASS CUDA를 사용할 수 있는 경우: optimizer step: cuda PASS

Try it yourself

잘못된 config 거절하기

원본 config는 타입·범위 전체를 검증하지 않는다. hidden_dim=0, num_heads=0, hidden_dim=10/num_heads=4를 거절하도록 __post_init__을 확장하고, tests/test_config_invalid.py에 실패 입력 테스트를 작성한다. 실행별 환경 JSON 저장도 추가한다.

힌트 보기

type(value) is int·양수·hidden_dim % num_heads를 검사한다. bool은 int의 subclass이므로 isinstance(value, int)만 사용하면 True를 허용할 수 있다. seed.py 안에서 PYTHONHASHSEED를 설정해도 현재 프로세스의 hash seed가 다시 초기화되지는 않는다.

Check your understanding

loss.backward()만 호출했을 때, weight 값은 자동으로 바뀌는가?

Verification

  • CPU와 CUDA에서 tensor 연산·backward·optimizer 한 step을 확인한다.
  • 같은 seed의 작은 CPU 입력을 비교하고 잘못된 config의 필드·타입·범위를 거절한다.
  • OS·Python·torch·CUDA·driver·GPU·VRAM·BF16 지원과 실행 명령을 JSON·로그로 남긴다.
