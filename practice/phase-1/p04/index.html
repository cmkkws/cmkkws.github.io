Learning goal

nn.Module·nn.Parameter로 Linear와 두 층 MLP를 구성하고 같은 weight의 reference와 값·gradient를 비교한다.

입력·출력 계약

Linear는 [...,in] → [...,out], weight는 [out,in]다. MLP는 fc2(activation(fc1(x)))이며 하위 모듈의 parameter가 부모에 등록되어야 한다.

파일 역할

src/llm_lab/ops/linear.py
CustomLinear의 parameter·초기화·forward와 ReLU/SiLU MLP를 정의한다.
tests/test_p04_custom_linear.py
동일 weight의 forward/backward, XOR overfit, parameter 이름과 state_dict를 검사한다.

Follow along

  1. 01

    Parameter와 shape 읽기

    CustomLinear.__init__에서 super().__init__, nn.Parameter, bias=False의 register_parameter를 확인한다. plain Tensor를 속성에 넣는 경우와 parameters()의 차이를 설명한다.

    확인할 결과 · 예상 형태

    weight:[out,in], bias:[out]. 입력의 마지막 in 축만 Linear가 변환한다.

  2. 02

    직접 값 확인

    scripts/trace_linear.py를 만들고 아래 코드를 저장한다. no_grad는 이 예제의 parameter 값 복사에만 사용한다.

    확인할 결과 · 예상 형태

    output=[[-0.5]], dx=[[2.0,-1.0]], parameters=['weight','bias'].

  3. 03

    예제 실행

    예제를 실행한 뒤 [B,T,2] 입력에서도 마지막 축이 1이 되는지 확인한다. bias=False인 경우 named_parameters에는 weight만 남는다.

    확인할 결과 · 예상 형태

    2×1−1×3+0.5=-0.5. 입력 gradient는 weight의 두 성분이다.

  4. 04

    Reference·XOR·등록 검증

    reference에 weight/bias를 copy_한 다음 값을 비교하는 순서를 확인한다. 두 입력 graph를 별도로 만들고 dx/dW/db를 비교한다. XOR 검사는 SiLU·hidden=16·Adam·300회 학습이며 최종 accuracy=1과 loss<1e-3을 요구한다.

    확인할 결과 · 예상 형태

    통과하면 3 passed. MLP 이름은 fc1.weight, fc1.bias, fc2.weight, fc2.bias다.

Source walkthrough

Parameter 등록 · L21–25

nn.Parameter 속성을 등록한다. bias=False에서는 None을 등록해 bias를 학습 목록에서 제외한다.

Try it yourself

Reference 조건 확장

bias=False, [B,T,in] 입력, FP64, ReLU/SiLU와 잘못된 activation을 검사한다. 등록된 parameter 수와 optimizer가 받은 tensor 수를 비교한다.

힌트 보기

같은 seed만 설정한 독립 초기화보다 weight를 직접 복사하는 비교가 명확하다. MLP의 device/dtype 변경은 구성 후 .to(...)로 적용한다.
