P08 · Byte tokenizer·작은 BPE

Phase 0Phase 1
목표·파일 역할따라하기코드 해설연습문제학습 체크
Phase 목록으로 돌아가기

Learning goal

UTF-8 byte ID와 special ID를 구분하고 pair 빈도·merge 순서·encode/decode의 실제 동작을 확인한다.

입력·출력 계약

기본 special ID는 endoftext=0·PAD=1, byte ID는 raw_byte+2다. 새 merge는 258부터 시작하며 decode는 special ID를 제거한다.

파일 역할

src/llm_lab/data/tokenizer.py
Byte vocabulary, pair 통계·치환, training과 merge-rank encoding, decoding을 정의한다.
tests/test_p08_tokenizer.py
반복 corpus의 300 vocabulary, 일반 UTF-8 복원과 special ID 포함 여부를 검사한다.

현재 기본 ID는 endoftext=0, PAD=1, byte=2–257이다. BOS는 정의하지 않는다. Decode는 special token을 제거하고 잘못된 UTF-8을 replacement 문자로 처리한다. 저장·불러오기는 확장 과제다.

Follow along

  1. 01

    ID 구간 확인

    __init__에서 special을 먼저 배치하는 순서를 읽는다. Default special 두 개가 있으므로 byte 'a'=97은 ID=99, 'b'=98은 ID=100이다. BOS는 현재 정의되어 있지 않다.

    확인할 결과 · 예상 형태

    Training 전 vocab_size=258. Special ID를 byte로 해석하거나 byte ID=0–255라고 가정하지 않는다.

  2. 02

    두 merge와 복원 추적

    scripts/trace_tokenizer.py를 만든다. 학습 corpus에서 'ab'는 네 번 등장하고, 다음에는 그 merge 두 개가 다시 합쳐진다. 이 축소 예제의 train corpus와 평가 문자열을 구분한다.

    확인할 결과 · 예상 형태

    merges={(99,100):258,(258,258):259}, ids=[259], decoded='abab'. Special PAD는 [1]이며, allowed_special=set()의 literal은 '<|pad|>'로 복원된다.

  3. 03

    예제 실행과 special 처리

    예제를 실행한다. encode의 기본 allowed_special은 등록된 special 전체다. decode는 이 ID들을 건너뛰므로 special 문자열이 포함된 원문의 완전 복원을 기본 설정에서 요구하지 않는다.

    확인할 결과 · 예상 형태

    일반 UTF-8은 byte vocabulary로 복원한다. 등록된 special의 literal을 보존하려면 해당 recognition을 끈다. Invalid UTF-8은 errors='replace' 정책이다.

  4. 04

    기본 복원과 special 검사

    테스트 corpus에만 train하고 이후 test_text를 encode한다. 테스트는 special ID의 포함을 검사하며 special 문자열을 포함한 decode 복원이나 save/load는 검사하지 않는다.

    확인할 결과 · 예상 형태

    통과하면 1 passed. Vocabulary는 항상 목표까지 커지는 것은 아니며 가장 많은 pair의 빈도가 2 미만이면 training이 먼저 끝난다.

Source walkthrough

Special ID 배치 · L20–28

Special을 먼저 0부터 배치한다. Default 두 개 이후 raw bytes는 offset 2를 적용한다. BOS는 없다.

Try it yourself

Tie-break와 저장·복원

빈도 동률에서 현재 처음 발견된 pair를 선택하는 정책을 기록한다. 명시적인 pair ID tie-break를 추가하고 special 목록·byte offset·merge 순서를 JSON에 저장해 재로딩 전후 token IDs를 비교한다.

힌트 보기

max(stats,key=stats.get)은 동률에서 insertion order를 따른다. 고정 corpus의 반복 재현과 corpus 순서에 독립적인 정책은 다르다. Held-out 텍스트로 merge를 다시 학습하지 않는다.
