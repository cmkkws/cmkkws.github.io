Learning goal

attention에서 token과 head가 섞이지 않도록, shape뿐 아니라 실제 값·축·메모리 배치를 추적한다.

입력·출력 계약

[B,T,D] → [B,T,H,d] → [B,H,T,d], D=H×d다. view는 축을 교환하지 않고 transpose는 축과 stride를 바꾼다.

Follow along

  1. 01

    작은 입력을 만들기

    학습용 추가 예제다. scripts/trace_heads.py를 만들고 아래 내용을 저장한다. 난수 대신 0–7을 쓰면 어느 값이 어느 head로 이동하는지 확인할 수 있다.

  2. 02

    값과 stride 추적

    아래 스크립트를 실행하고 다음 시각화의 head=2 결과와 비교한다. head 0의 두 번째 token은 [4,5]다. shape가 같아도 축을 잘못 해석하면 [2,3]이 들어갈 수 있다.

    확인할 결과 · 예상 형태

    input: [[[0, 1, 2, 3], [4, 5, 6, 7]]] heads: [[[[0, 1], [4, 5]], [[2, 3], [6, 7]]]] shape: (1, 2, 2, 2) stride: (8, 2, 4, 1) contiguous: False round trip: True

  3. 03

    원본 검증 실행

    split_heads의 view→transpose와 merge_heads의 transpose→contiguous→view를 파일 탐색기에서 따라 읽는다. contiguous는 이미 연속적인 tensor에는 복사를 요구하지 않는다. 이 왕복 입력에서는 merge의 역 transpose가 원래 stride를 되돌린다.

    확인할 결과 · 예상 형태

    [PASS] split_heads Shape Test Passed: ... [PASS] merge_heads & Value Reconstruction Test Passed. [PASS] batched_matmul Shape Test Passed: ... 1 passed ...

  4. 04

    값·gradient 검증 추가

    원본 테스트는 matmul의 shape를 검사한다. 아래 내용을 tests/test_p02_gradients.py에 저장해 einsum으로 같은 값을 계산하고 q·k의 gradient도 비교한다. 서로 다른 Tq=3·Tk=5를 사용해 정사각형 입력만 통과하는 구현을 피한다.

  5. 05

    추가 테스트 실행

    원본 검사와 추가 수치 검사를 함께 실행한다. expected는 작성한 추가 테스트까지 실행했을 때의 예상 형태다. 오차·dtype·seed와 지원하지 않은 입력을 기록한다.

Tensor trace

작은 값 0–7로 view·transpose·merge의 차이를 확인한다.

B=1 · T=2 · D=4 · d=2
[B,T,D] = [1,2,4]
token 00123
token 14567

원래 순서는 token → feature다. 색은 분할될 head를 나타낸다.

브라우저에서 계산하는 정수 예제다. 실제 PyTorch의 stride·값은 수업의 trace_heads.py로 확인한다. H=1에서는 비교의 차이가 드러나지 않는다.

Try it yourself

non-contiguous 원본 입력

x=torch.arange(24).reshape(1,4,6).transpose(1,2)로 [1,6,4] 입력을 만든다. head=2로 split→merge한 값이 x와 같은지 검사한다. num_heads=0·3, rank가 잘못된 입력을 거절하는 검증도 작성한다.

힌트 보기

view가 가능한지는 stride와 분할할 축의 관계에 달려 있다. 일부 non-contiguous 입력이 통과해도 모든 입력을 지원하는 것은 아니다. reshape의 복사 가능성 또는 명시적인 contiguous 정책을 정하고 ValueError로 입력 조건을 설명한다.
